## 现象

1. 同船多 lot 的「显式 priority」曾只接到 `match_release_batch`，次日才补到 `infer_candidate_context`（打地鼠）。
2. `all_loaded` 批次不应再接新发运；匹配 open 集虽已是 `loading|enriched`，缺回归夹住。
3. 满量/计划箱数达上限后无统一闸门，依赖人工改 `all_loaded` + 完成 match rule。

## 修复

1. `match_release_batch`：分票计划 `status=completed` 或 `allocated>=planned` 的 lot **排除** open 候选。
2. 测试夹住：
   - `all_loaded` → `no_open_batch`
   - completed match rule 不挡另一 open lot
   - 满 plan 排除后落到下一 lot
   - **入口矩阵**：match 与 infer 同分路径对同一 fixture 结论一致（均 `explicit_priority`→lot03）
