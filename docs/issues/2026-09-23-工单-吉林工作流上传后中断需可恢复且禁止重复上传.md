# 工单：吉林工作流上传后中断需可恢复且禁止重复上传

- **日期**：2026-09-23

- **范围**：吉林金钢发运文本链 / `jljg_departure_text_chain`
- **theme**：T7_外部动作幂等

## 现象

高栏309 lot01 的 51车/102箱在门户上传完成后，反查调用因未携带订单号而扫描全量历史，运行被中断。已有事实、门户记录均正确，但任务停留在 `running`；若直接 force 重跑，现有上传函数可能再次提交同一批箱级记录。

## 根因

当前工作流将“入库、生成 Excel、门户上传、反查、微信发送”串在单次执行内，未把已完成步骤的精确结果持久化为可恢复检查点。外部动作日志只记录计划，任务中断后没有统一的恢复/收尾路径。

## 修复方向

1. 将每个外部步骤的已完成事实（事件 YDID/箱号摘要、门户 `present+unique` 结果、Excel 路径、群附件回读）持久化到任务输出与外部动作日志。
2. 重试只能从第一个未完成步骤开始；已有 `portal_id` 或门户反查已存在的箱级记录必须跳过上传。
3. 提供单事件恢复入口，禁止用全局 pending 或 `force` 重跑替代恢复。
4. 为“上传成功后中断、再执行”补回归测试，断言门户请求次数不增加且 Excel/微信仅各一次。

## 当前临时处置

本次高栏309事件已做精确门户反查、Excel 生成和群附件回读后人工收口；没有重跑上传步骤。后续同类事件在本工单完成前必须先核查外部动作日志与门户现状。
