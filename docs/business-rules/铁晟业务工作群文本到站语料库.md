# 铁晟业务工作群文本到站语料库

## 目的

该语料库约束“检装车文本触发器”的到站识别与跨站隔离。文本不是车号或分票的
权威来源，只提供“哪一站、哪条船、预期多少车”的 rendezvous 信号；车号和 lot
仍以检装车通知单及 95306 为准。

## 当前基线

- 来源：`data/sop_agent.db` 的 `message_inbox`，群名 `铁晟业务工作群`
- 时间：2026-07-01 至 2026-07-31
- 原始命中：202 条带站点与 `N节/N车` 的文本
- 去重后：138 个归一化形态
- 文件：`tests/fixtures/workgroup_station_text_corpus_2026-07.json`
- 更新工具：`PYTHONPATH=src python3 scripts/build_workgroup_station_text_corpus.py`

归一化只用于同类文本聚合：去空白，并把数量替换成 `{N}节`；每个形态保留第一条
消息的 inbox ID、微信消息 ID、时间和原文，以便回溯。

## 识别规则

1. 先按站名切段，再在本段内读取已知 SOP 船名和车数；不得按船名跨站找最近车数。
2. `汐子/汐子铁/沙子` → 汐子；`朝阳西/朝阳西铁/朝阳铁` → 朝阳西；`四平铁/四平镍`
   → 四平；`新台` → 新台子。
3. `凌东/凌源东` → 凌源东、`乌铁/乌兰浩特` → 乌兰浩特。这些目前不是 SOP
   触发目标，但必须作为硬隔离段。
4. `53节汐子铁宝丽` 的数量归汐子段；`宝丽，3节乌铁春日莲花` 的 3 节归乌兰浩特段。
   只有紧邻下一站名的 `N节<站名>` 才视为下一站前缀；`N节，<站名>`仍归前一站。
5. 明确写出非 SOP 到站时，不得退回“船名→项目默认到站”的旧兜底。没有任何站名的
   单一流文本才保留旧兜底，以兼容历史格式。

## 典型样本

| 消息 | 期望识别 |
| --- | --- |
| `煤四，53节汐子铁宝丽，3节乌铁春日莲花` | 宝丽 / 汐子 / 53；乌兰浩特段不触发 |
| `煤五凌东铁宝腾海51节` | 凌源东非 SOP 段，不创建朝阳钢铁任务 |
| `煤五朝阳西铁宝腾海51节` | 宝腾海 / 朝阳西 / 51 |
| `煤五 汐子铁 宝丽19节 鞍子河10节共29节` | 宝丽 / 19 与鞍子河 / 10，均为汐子 |
| `煤五，汐子铁，鞍子河13节，朝阳西，马兰幸福14节，实装27节` | 两个不同 SOP 站段，各自独立触发 |

对应自动化回归见 `tests/test_text_station_segments.py` 和
`tests/functional/test_inspection_text_trigger.py`。
