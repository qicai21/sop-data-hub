# 工单：微信附件假成功后被幂等键阻断补发

- **日期**：2026-09-14
- **状态**：待处理
- **范围**：朝阳钢铁检装车链、`send_shipping_excel_wechat`、`external_action_log`
- **theme**：T4_外发证据 / T5_幂等

## 现象

朝阳钢铁欧律狄克 2026-09-14 的 53 车事件：

1. 文本触发链在 13:53 记录了“发运数据 欧律狄克 共53车”，
   `external_action_log` 也记为 `send_shipping_excel_wechat=executed`。
2. 数据单发群月度聊天账本只有该文字，没有同名 xlsx 附件。
3. 15:22 真实检装车通知单到达后，系统识别同一 53 车并正确避免重复入库，
   但因既有外发幂等键已经是 `executed`，Excel 被“已发”跳过，无法自愈。

## 已核验证据

- 实装车：53；通知单另有 3 节排车/缺陷，不应入库。
- 本地车事实：53 车已在 `wagon_shipments`，来源文本 `wx_2026-09_1225`。
- 发运 Excel：
  `.../欧律狄克/lot04/excel/2026-09-14/欧律狄克发运_2026-09-14_53车.xlsx`。
- 微信动作：`external_action_log.id=422` 显示 `executed`，但聊天账本中不存在附件记录。
- 真实检装图：`wx_2026-09_1288`，其 Excel 节点因同一幂等键跳过。

## 根因

`send_excel.send_to_wechat()` 以 `wx-ui-bridge` 子进程退出码为成功依据；
`external_action_log` 随即标记 `executed`。当前没有独立的微信群附件回读/确认状态。
因此 UI 自动化未真正完成附件发送时，本地仍产生不可重试的“已执行”记录。

## 修复方向

1. 将“UI 调用完成”与“附件已在目标群可见”拆成不同状态，后者才可终态成功。
2. 对 `planned`、`failed`、`unverified` 外发动作建立可审计的恢复/补发路径；不得把
   未验证动作永久作为幂等终态。
3. 真实通知单重放时，若现有外发动作缺少附件送达证据，应允许受控补发，而不是直接跳过。
4. 补回归测试：桥接返回 0 但没有附件确认时，后续同事件必须可以恢复补发，且不得重复入库。

## 本次人工处置

已于 2026-09-14 22:xx 通过 wx-ui-bridge 单独补发文字和 xlsx。桥接命令返回成功；
由于 wx-ops-agent 对数据单发群的实时回读未能获得可用表映射，附件送达仍需下一轮聊天账本
或人工群内查看确认，不能将本次补发记为已验证送达。

## 验收

1. 模拟 bridge 返回 0、附件确认缺失的场景，动作不得进入不可恢复 `executed` 终态。
2. 同事件重放可仅补发附件，不重复写 `wagon_shipments`、不重复上传门户。
3. 目标群聊天账本可找到与动作记录关联的文件名、时间、大小/路径证据后，才标记送达。
