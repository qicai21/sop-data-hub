# 工单: 中唐检装车 JSON 层汐子站名 OCR 归一缺失

## 背景

中唐特钢 `宝丽` 检装车通知单的抽取 JSON 中出现：

- `cargo_info_raw = "沙子铁矿粉"`

业务上这里应归一为 `汐子铁矿粉`。

## 现象

- 项目推断/路由层已经有 `沙子 -> 汐子`、`沱子 -> 汐子` 等闭集纠错
- 但检装车 JSON 落盘层仍保留原误识文本
- 导致：
  - JSON 结果本身不可信
  - 后续候选推断依赖 `cargo_info_raw` 时仍会受误识干扰

## 根因

`inspection_slip` 引擎在 `_normalize_rows()` / `_apply_inheritance()` 阶段没有对
`cargo_info_raw` 做站名 OCR 归一；纠错只在更后面的路由/项目推断层生效。

## 修复目标

1. 在检装车引擎中，对 `cargo_info_raw` 进行闭集站名 OCR 归一
2. 归一后的值直接进入 JSON 落盘结果
3. `cargo_info_effective` 与后续匹配链共享同一口径

## 验收

- `沙子铁矿粉`、`沱子铁矿粉` 在 JSON 中直接落成 `汐子铁矿粉`
- 既有 `汐子铁矿粉` 样例不受影响
- inheritance / anchor 检测相关测试继续通过
