# 工单：中唐宝丽货运信息字段错位导致 lot4 挂起

- **类型**：数据修复 / 匹配逻辑缺陷
- **状态**：已处理
- **项目**：中唐特钢

## 现象

2026-07-18 `中唐特钢发运群` 中，11:25:40 收到宝丽货运文本：计划号 `90260700052`、合同号 `ZLZT-2026071401`、麦克粉、10000 吨；11:25:47 收到宝丽第四次出港计划通知单。系统已建 `lot04`，但货运信息未补入，批次停在 `pending_freight`。

## 根因

1. 宝丽 lot01-lot03 的计划号历史上存于 `release_batches.order_identifier`，而中唐补充货运匹配器只将 `plan_id` 非空视为已填计划号。
2. 因此 lot03 与新建的 lot04 同时被判定为“缺计划号”，命中歧义保护，货运文本未写入任何批次。
3. 歧义分支被记为任务完成，未在相邻出港计划通知单入库后重试。

## 修复范围

1. 中唐匹配器将 `plan_id` 和历史兼容字段 `order_identifier` 统一视为计划号占位；精确匹配同时支持两字段。
2. 将宝丽 lot01-lot03 的历史计划号镜像补入 `plan_id`，不删除原 `order_identifier`。
3. 将已确认的 `90260700052 / ZLZT-2026071401 / 麦克粉 / 10000 吨` 补入宝丽 lot04，并推进到 `enriched`。
4. 添加回归测试：已有批次仅在 `order_identifier` 记录计划号时，新货运信息应唯一匹配新的 lot，不得误挂歧义。

## 验收

- 宝丽 lot04 的 `plan_id`、合同号、货物品名、计划量齐全，状态为 `enriched`。
- 宝丽 lot03 不再被中唐补充货运匹配器误判为“缺计划号”。
