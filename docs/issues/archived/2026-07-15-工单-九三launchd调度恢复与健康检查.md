# 工单：九三 launchd 调度恢复与健康检查

- 日期：2026-07-15
- 状态：已完成
- 优先级：P0

## 现象

`jiusan-sync` 与 `jiusan-bulk-report-ingest` 的用户 LaunchAgent 文件被写成 JSON 数组，不是 plist；`plutil -lint` 无法通过，重启后 job 不会加载。

## 目标

1. 在仓库保留可校验的 plist 模板。
2. 提供可重复执行的安装/重载脚本，并对现有损坏文件做备份。
3. 提供 health check，明确报告必需九三 job 是否已加载及 plist 是否有效。
4. 加入模板结构测试，并在本机完成 `plutil` 与 `launchctl` 验证。

## 验收

- 两个 plist 均为有效 XML plist。
- `launchctl list` 可见两个 label。
- 不触发微信发送或门户上传。

## 实施结果

- 发现 live-service、text-watch 也同样损坏，已一起恢复为四个版本管理的 plist 模板，均通过 `plutil -lint`。
- 新增安装/重载与 health check 脚本；损坏的本机 plist 会先备份。
- 已在本机加载 live-service、text-watch、`jiusan-sync`、`jiusan-bulk-report-ingest`，并确认晨报对账 job 同时在载。
- `restart_all.sh` 已纳入三个九三任务，避免下一次代码重启只拉消息链、不拉对账链。
