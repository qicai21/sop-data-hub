# 需求:散粮发运 sync 按船拆分(`sync_jiusan_bulk_wagons` 写死和谐1 → 诚信混入、lot02 超发)

- **提出日期**:2026-06-20
- **提出场景**:九三大豆「诚信」轮 2026-06-19 首发散粮 30节,与和谐1 的 20节同列(七道 50节)发出。同步后 **和谐1 lot02 剩余 -2072t(超发)**,诚信 lot02 仍为 0 —— 诚信的散粮被全算进了和谐1。
- **严重度**:中高 —— 多船并行期散粮**计数/重量/进度全部错位**,lot02 出负数;且会随每趟持续恶化。
- **类型**:功能缺陷 / 改造

---

## 根因

`scripts/sync_jiusan_bulk_wagons.py` **写死单船**:
```python
SHIP = "和谐1"
BATCH_ID = "9d9d6e8364df7448119d2b28186c497b846a1cbb"   # jiusan|和谐1|lot02
...
"batch_id": BATCH_ID, "ship_name": SHIP,      # 每票一行,全挂和谐1
```
它从 95306 抓散粮货票,**不分船全部 INSERT OR REPLACE 到和谐1 lot02**(key=`sha1("bulk"|ydid)`)。没有"诚信"概念。

**为什么不能简单手工改 wagon_shipments**:sync 每 30min(launchd)幂等重写,手工改的 batch_id 下一轮就被覆盖回和谐1。必须改 sync 本身。

**为什么不能靠 95306 自动拆**:诚信、和谐1 两船散粮**到站相同(新台子)、收货人相同**,95306 货票里无任何字段能区分谁是谁。**唯一事实源 = 港方每趟出的「简装车通知单」**(标了"诚信30节/和谐1 20节" + 逐车车号)。

**首条数据**:2026-06-19 七道 50节 = 诚信30(24×L18+6×L70) + 和谐1 20(16×L18+4×L70),**50/50 命中 wagon_shipments、ydid 全唯一**。(序号2 经库反查确认 = 8101357,非通知单 OCR 的 8011357。)
