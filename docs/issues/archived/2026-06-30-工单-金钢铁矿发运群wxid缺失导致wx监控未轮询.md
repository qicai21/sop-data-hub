# 工单:金钢铁矿发运群 wxid 缺失导致 wx 监控未轮询

- **类型**:运行配置/微信监听
- **发现日期**:2026-06-30
- **发现来源**:用户发现 wx-ops-agent 监控似乎未起来
- **状态**:已处理
- **严重度**:高 —— `wechat-ops-agent` 主 daemon 虽运行,但 GROUP005 没有实际 DB wxid,会跳过该群轮询

## 现象

`wechat-ops-agent` launchd 进程运行正常,日志显示每轮启动 5 个监听群:

- 铁晟业务工作群
- 数据单发群
- 金钢铁矿发运群
- 九三大豆发运群
- 中唐特钢发运群

但实际 `Polling DB` 只有 4 个群,没有 `金钢铁矿发运群`。

## 根因

`wx_config.json` 中 GROUP005:

- `id=GROUP005`
- `name=金钢铁矿发运群`
- `wxid=""`

`wx-ops-agent` 需要真实微信 DB wxid 才能查询消息表。wxid 为空时,该监听项只存在于配置展示层,不会实际轮询 DB。

真实 wxid 从 `wx-ops-agent/data/address_book.json` 查到:

- `金钢铁矿发运群-[GROUP005]`
- `wxid=39330980598@chatroom`

上游配置缺失位置:

- `config/project_sops/jilin_jingang.yaml`
- `listen_tasks` 中 GROUP005 未写 `wxid`

## 修复

- 给 `jilin_jingang.yaml` 的 GROUP005 监听项补 `wxid: "39330980598@chatroom"`。
- 重新导出 `wx_config.json`。
- 重启 `com.qicai21.wechat-ops-agent`。

## 验收

- `wx_config.json` 中 GROUP005 `wxid=39330980598@chatroom`。
- wx daemon 日志中出现 `Polling DB for 金钢铁矿发运群`。
- `data/last_seen_timers.json` 出现/更新 `39330980598@chatroom`。

## 落实记录(2026-06-30)

- 当前 WeChat 通讯录确认:
  - `金钢铁矿发运群-[GROUP005]`
  - `wxid=39330980598@chatroom`
- 已在 `config/project_sops/jilin_jingang.yaml` 的 GROUP005 监听项补齐 `wxid`。
- 已通过 `wx_config_exporter` 导出运行配置。
- 重启/观察后,daemon 日志已出现 `Polling DB for 金钢铁矿发运群`。
