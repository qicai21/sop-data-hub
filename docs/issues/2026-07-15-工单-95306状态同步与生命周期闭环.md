# 工单：95306 状态同步与生命周期闭环

- 日期：2026-07-15
- **状态**：部分完成 — 活跃船状态同步/箱级回写已日常化；原设计工单中跨表与 lifecycle 闸口细则仍需收口
- 优先级：P1

## 现象

95306 已经到站/交付的记录未稳定回写 `wagon_shipments` 与 `wagon_container_shipments`。现有手工同步器没有接入调度，且按车号兜底会把循环车匹配到较晚一趟；批次状态更新也绕过 lifecycle。

## 分析结论与本轮边界

本轮只完成设计、数据核对与回归测试方案；在确认跨表口径、批次推进规则和调度位置前，不直接启用自动批量回写。

当前实现不得直接启用，原因如下：

1. 读取 `wagon_shipments` 时没有取出 `ydid`，实际只能用车号/到站匹配循环车。
2. 回写只覆盖 `wagon_shipments`，吉林的集装箱事实表未进入同步。
3. 批次状态被直接覆盖为 `delivered`，没有走 lifecycle transition，且一条车更新就可能影响整批。
4. 现有状态机和 `lifecycle_closeout` 已有“全车交付、集装箱静默两天、散粮剩余吨位”等业务闸；新同步器必须只更新事实状态，再复用该入口。

## 后续目标

1. 以 `ydid` 作为唯一优先锚点；无 ydid 时只输出待核对，不按“最新车号”猜配。
2. 覆盖 wagon 与 wagon-container 两张事实表。
3. 通过既有 lifecycle 入口推进批次，避免直接覆盖 `dispatch_status`。
4. 输出同步报告并进入确定的调度链。
