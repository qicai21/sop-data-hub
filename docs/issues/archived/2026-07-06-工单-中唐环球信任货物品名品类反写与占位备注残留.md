# 工单:中唐环球信任货物品名品类反写与占位备注残留

- 日期:2026-07-06
- 项目:中唐特钢
- 船名:环球信任
- 类型:数据修正 / 历史 backfill 口径修复
- 状态:已修复

## 背景

用户核对发现,环球信任在系统内显示的货物字段疑似反写:

- 货物品名应为:`混合粉`
- 货物品类应为:`铁矿粉`

同时 release batch 备注中残留:

```text
待补充:大船+合同 (plan_id 已挂)
```

但当前批次的 `plan_id` / `contract_no` 已经补齐,该备注不应继续展示。

## 已核实事实

当前 `release_batches` 中 6 条环球信任批次均为:

- `cargo_name=混合粉`
- `cargo_product_name=铁矿粉`
- `commissioner_note=待补充:大船+合同 (plan_id 已挂)`

按当前系统字段语义:

- `cargo_name`:用于品类/匹配类别,应为 `铁矿粉`
- `cargo_product_name`:用于发运 Excel / 看板展示的具体货物品名,应为 `混合粉`

关联的 `release_dispatch_match_rules` 也继承了 `cargo_name=混合粉`,需要同步修正为 `铁矿粉`。

## 根因

历史脚本 `scripts/split_zhongtang_lots_by_plan.py` 在拆分环球信任 lot 时复制了旧字段,
并写入占位 `commissioner_note`。后续 plan / contract 已通过人工或 enrichment 补齐,
但没有清理占位备注,也没有把品类/品名字段按现行口径纠正。

## 修复要求

1. 修正环球信任所有 release batch:
   - `cargo_name=铁矿粉`
   - `cargo_product_name=混合粉`
   - 清理 `commissioner_note` 中已过期的待补充占位。
2. 修正环球信任 release dispatch match rules:
   - `cargo_name=铁矿粉`
   - `matching_str` / `matching_tokens_json` 中 cargo token 改为 `铁矿粉`。
3. 修正历史 backfill 脚本,避免未来重跑再写反或写入过期占位。
4. 保留 source_json 中历史来源说明,不把历史审计痕迹伪装成新来源。

## 处理记录

  - `cargo_product_name=混合粉`

  - 品类固定为 `铁矿粉`
  - 不再写入 `待补充:大船+合同 (plan_id 已挂)` 占位备注
