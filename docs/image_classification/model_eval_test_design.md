# 本地 VLM 识别能力对比测试设计

- **日期**:2026-06-25
- **目的**:在本项目真实业务图片 + 已积累的正确映射上,对比两个本地模型的识别能力,决定是否升级。
- **被测模型**:
  1. `Qwen3-VL-8B-Instruct-4bit`(当前在用,baseline,MLX,:8018)
  2. `Qwen3-VL-30B/35B-A3B-4bit`(候选,MoE;**需确认是 VL 多模态版**,否则读不了图)
- **跑法**:各模型起一个 MLX-VLM `/generate` 端点;harness 把 `BusinessGroupImageClassifier.service_url` 指向各端点,同一套 prompt + 同一冻结评测集,逐模型跑、对 ground truth 打分。

---

## 一、评测集(冻结、可复现)

来源 = `message_inbox`(`classification_label` 人工校正过的类别 + `extraction_json_path`)。已有标注规模:

| 类别 | 张数 | 角色 |
|---|---|---|
| 检装车通知单 | 184 | 目标类 + 提取 GT |
| 出港计划通知单 | 91 | 目标类 + 提取 GT |
| **日现场工作记录表** | 175 | **关键易混负样本**(无标题、版式像检装单) |
| 请车表 | 30 | 易混负样本 |
| 手写箱号车号表 | 114 | 手工分票第二钥匙类 |
| 照片-集装箱内/装卸/敞车/mark/工人 | ~771 | 现场照片(分类干扰) |
| 耗材统计表 / other / error | 21/29/50 | 长尾 |

**构建脚本产物**:`eval_set.jsonl`,每行 `{image_path, gt_category, gt_extraction_ref, source_msg_id}`。
- 解析 `raw_standard_image_path`/`msg_path` 定位真图,**过滤掉指向 xlsx / 缺失文件的脏行**。
- 分层抽样(每类全取或封顶 N,易混簇 检装单/日现场/请车/手写箱号 全取)。
- **冻结**:版本化存盘,两模型跑同一份。

## 二、提取 ground truth(避免循环验证)

⚠️ `*_result.json` 是**旧 8B 模型的产出**,直接当 GT 测 8B 会自我循环。**改用下游已被业务确认的记录做 GT**:
- **出港计划** → 该图创建的 `release_batches`(船名/数量吨/计划号/合同号/发货收货单位/到站)——这些进了真实放货、被确认。
- **检装车通知单** → 该图驱动的 candidate/`wagon_*`(序号→车号、拆段→船、日期、道线、车数)。
- 对照键:`source_message_id` / `source_file` 回连图片。
- 没下游记录的,退回 `*_result.json` 但**标注为"弱GT"**,分开统计。

## 三、四个考量 → 指标

### A. 分类准确(考量1)
- 跑 `classify()` 全评测集 → 混淆矩阵 + 各类 P/R/F1 + 总准确率。
- **重点指标**:
  - **检装单假阳率**:日现场记录表/请车表 被误判成检装单的比例(= "标题反向铁律"遵守度;这正是 2026-06-19 日报误判根因)。
  - 检装单召回(漏判率)。
  - 易混簇(检装单/日现场/请车/手写箱号)子混淆矩阵单列。
- `detected_title` 命中率(模型是否如实报告看到的标题)。

### B. 内容识别 准确性 + 效率(考量2)
- 跑提取 prompt(`DEPARTURE_PLAN_EXTRACTION_PROMPT` + 检装单提取)在两目标类上。
- **字段级精确匹配率**,按重要性加权:
  - 出港计划关键字段:船名、数量(吨)、计划号、合同号、发货单位、到站。
  - 检装单关键字段:序号→车号映射、拆段→船、日期、道线、车数。
- **归一规则遵守**:发货单位 新德/新儒→新僡 等(prompt 第10条);朝阳 tyrjzsx 不在此(图片侧)。
- **完整双射**:检装单 N 车与序号零差异(harness 直接比对车号集合)。
- 出港计划"多 remark/全船"场景(场景A/B)拆分是否正确。

### C. prompt→识别动作 转化(考量3)
- **JSON 有效率**:可解析、字段不增删、无 markdown 包裹。
- **指令遵守**:
  - 标题硬锚(有"检、装车通知单"才判检装单)+ 反向铁律(无标题即使版式像也不判)。
  - "不是本类型只输出 `{}`/拒答"路径是否正确触发(给非目标图,看是否乱抽)。
  - 命名归一是否执行。
- 即"给定 prompt 能否稳定转成正确结构化动作"的量化。

### D. 整体效率(考量4)
- 单图延迟 p50/p95(分类 + 提取分开)。
- 吞吐(图/分)。
- 4bit 显存/内存峰值(8B vs 35B-A3B,MoE 激活 3B 但权重大)。
- 解码 tokens/s + 模型冷启动加载时长。
- **权衡量化**:35B-A3B 若更准,贵多少(内存/延迟)——给准确率↔速度 散点。

## 四、Harness

- 复用 `src/sop_hub/classifier/`(classify + 提取),仅换 `service_url` 指向各模型端点。
- 两端点:8B :8018(现成)、35B-A3B 另起一端口(同 MLX-VLM server,换 `--model`)。同机串行跑避免抢内存。
- 评测脚本 `scripts/eval_vlm_models.py`:读 `eval_set.jsonl` → 每 (图×模型) 跑分类+提取 → 对 GT 打分 → 聚合 → 出对比报告(准确率/效率表 + 混淆矩阵 + 字段级 + 权衡)。
- 同图同 prompt,**两模型唯一变量 = 模型本身**。

## 五、执行步骤

1. 写 `build_eval_set.py` → 生成冻结 `eval_set.jsonl`(+ 过滤脏行 + 接下游GT)。
2. 起 35B-A3B 的 MLX-VLM 端点(确认 VL 版 + 端口)。
3. 跑 `eval_vlm_models.py --model 8b` 和 `--model 35b`。
4. 出对比报告:四考量各一节 + 总结建议(是否升级 / 哪类该用哪个 / 是否分级路由:分类用小、提取用大)。

## 六、可选增强

- 同一模型多次跑测稳定性(VLM 输出抖动)。
- 难例集(历史误判:1891349/1891358 串船、长航滨海14+宝腾海10 多船拆图)单独跑。
- prompt 消融:有/无"反向铁律"对检装单假阳率的影响(验证 prompt 工程价值)。
