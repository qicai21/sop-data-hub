# 工单: 测试默认隔离真实微信发送

- 日期: 2026-07-06
- 类型: 测试防护 / 开发环境隔离
- 状态: 已处理

## 背景

在补 `中唐货运匹配挂起不重试` 的功能测试时,测试用例误触发了
`workflow_task_executor._zt_retry_or_timeout()` 的超时告警分支,真实向
`[GROUP013]` 发送了两条“中唐货运超时未匹配批次”消息。

根因不是线上业务异常,而是:

1. 测试把 `message_inbox.created_at` 设成了旧时间,命中“超 24h 告警”条件。
2. 用例没有显式 mock `send_to_wechat()`。
3. 当前测试仓默认并没有全局保险丝阻止真实微信发送。

## 目标

1. 所有 pytest 用例默认禁止真实 `send_to_wechat()` 外发。
2. 个别需要验证发送行为的测试,再局部覆盖 monkeypatch。
3. 避免后续再因忘记 mock 而向 `数据单发群` 发真实消息。

## 处理

1. 在 `tests/conftest.py` 新增 `autouse` fixture:
   - 默认 monkeypatch `sop_hub.sop.send_excel.send_to_wechat`
   - 返回固定成功对象,不触发真实外发
2. 保留现有局部 monkeypatch 测试不变:
   - 局部覆盖时,pytest 的就近 monkeypatch 仍然生效

## 验证

至少覆盖以下带发送风险的测试集:

- `tests/functional/test_zhongtang_freight_supplement.py`
- `tests/functional/test_inspection_text_trigger.py`
- `tests/functional/test_pending_match_verifier_retry_before_timeout.py`
- `tests/functional/test_e2e_chaoyang_zhonglianfa.py`

## 结论

从本工单起,测试默认进入“禁真实微信发送”模式;要验证发送参数时,必须在具体测试里显式覆盖该桩。
