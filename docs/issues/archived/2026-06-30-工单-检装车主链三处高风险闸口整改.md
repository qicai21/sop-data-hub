# 工单:检装车主链三处高风险闸口整改

- **类型**:流程闸口整改
- **发现日期**:2026-06-30
- **状态**:已处理
- **严重度**:高

## 背景

复盘近期“检装车通知单/发车文本已出现,但没有按票入库、制作发运 Excel、发送/上传”的工单后,仍有三类高风险开口:

1. `pending_freight` 批次无法稳定参与多船检装车拆分和车列事实入库。
2. 检装车文本触发器的 `already_handled_by_notice_chain` 分支可能误复用旧 `matched` 候选。
3. `pending_match_verifier` 只按 `message_inbox.inspection_candidate_id` 回查 inbox,回链漏写时会 `no_inbox_link`。

## 关联工单

- `2026-06-30-工单-检装车拆分不应被货运信息闸阻断入库.md`
- `2026-06-30-工单-检装车文本触发器误复用旧matched候选.md`
- `2026-06-28-工单-候选未回填inbox链接致verifier永不重试.md`
- `2026-06-29-调查-中唐55车检装单拆船未触发.md`

## 设计原则

- **车列事实层**:release_batch 已存在即可参与检装车船名锚点拆分和 95306 车列入库;`pending_freight` 不再阻断事实归属。
- **发运输出层**:发运 Excel、微信发送、收货人系统上传仍要求货运信息齐备;`pending_freight` 只能停在“已入库待货运信息”。
- **事件边界**:文本触发器判断“通知单链已处理”时,必须以本次触发文本时间和到站为边界,不能只靠船名和车数。
- **回链兜底**:verifier 先按 inbox 反链查,查不到时用候选 `message_id` 兜底,并尽量补写 `message_inbox.inspection_candidate_id`。

## 验收标准

- 两船检装车单中,船 A 为 `loading/enriched`,船 B 为 `pending_freight` 且无 active rule 时,仍能拆出船 B 段并归属到对应 release_batch。
- `pending_freight` 批次的车列可写入 `wagon_shipments`,但链路停在 `awaiting_freight_info`,不生成/发送 Excel,不上传收货人系统。
- 同一船连续发车时,当天文本触发不能被前一天旧 `matched` 候选短路。
- `message_inbox.inspection_candidate_id` 漏写时,verifier 可通过候选 `message_id` 找回 inbox 并继续重试。

## 处理记录

代码改动:

- `src/sop_hub/data_agent/agent.py`
  - `_split_payload_by_ship_rules()` 在 active rule 之外,增加 `release_batches` 中 `pending_freight/enriched/loading` 的船名锚点 fallback。
  - 多船拆分命中 batch fallback 时,候选直接写入 `_split_group_release_batch_id`,后续 ingest 可归属到对应 release_batch。
  - 候选创建后同步回填 `message_inbox.inspection_candidate_id`,避免 verifier 找不到 inbox。
- `src/sop_hub/sop/match_release_batch.py`
  - 新增 `allow_pending_freight_for_facts` 参数;默认不变。
  - 检装车事实入库链可显式允许 `pending_freight` 匹配,但输出层仍独立拦截。
- `src/sop_hub/sop/workflow_task_executor.py`
  - 文本触发器的旧 `matched` 短路改为以本次触发文本 `received_datetime` 为事件窗口,并要求 destination 一致。
  - 活跃候选保留原 `now` 临近 fallback,避免正常 rendezvous 退化。
  - 检装车链在车列事实入库后,若批次仍为 `pending_freight`,标记 `pending_freight_info` 并停在 `awaiting_freight_info`,不生成/发送发运 Excel,不上传收货人系统。
- `src/sop_hub/sop/pending_match_verifier.py`
  - `_find_inbox_id()` 增加候选 `message_id` 兜底,并补写 inbox 反链。
  - verifier 扫描 `pending_freight_info`,货运信息补齐后可继续重试推进。
- 测试:
  - `tests/test_chaoyang_rendezvous_fix.py`
  - `tests/test_pending_freight_inspection_guards.py`
