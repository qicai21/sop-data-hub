## 根因

1. `chaoyang.yaml` 明确规定：`order_identifier` = 回运计划号 = `upload_and_verify(transport_plan_no=…)`  
2. **`workflow_task_executor` step 6c 调用 `upload_and_verify` 时未传 `transport_plan_no`**  
3. `upload_and_verify` 无计划号时 fallback：wmwm01 **30 天窗 + 船名**，`next(p for p if ship_cname==船名)` → **同船多计划时取第一条**  
4. 马兰幸福 lot1/lot2 与 lot3 并存 → 第一条常为旧计划 **HY26062603（lot2）**，车却来自 lot3 batch

```
excel/match → lot03 (HY26071703)  ✓
upload_and_verify(ship only) → 门户 plan HY26062603 (lot2)  ✗
```

## 修复

1. 上传前读 `release_batches.order_identifier`（空则 `plan_id`），**必传** `transport_plan_no`；缺失则阻断上传。  
2. `upload_and_verify`：无 `transport_plan_no` 且同船命中 >1 条 plan → **硬失败**，禁止猜第一条。  
3. 测试：`tests/test_chaoyang_transport_plan_selection.py`
