## 1. 背景与业务事实

**敞车装车项目**(中唐特钢、朝阳钢铁这类**整车散装**业务,区别于吉林金钢的集装箱业务)有一个固有现象:

- 一船货物到港,按**整车标载**发运,每车按车型装(C70 ≈ 70t/车)。
- 船的到货总吨数**除不尽整车标载** → 每条船/每个批次发运完后,港口会剩一截**零头尾货**(不足一车),留在港口某个**货位**上。
- 这部分尾货目前**没有系统记录**,只能靠人记,容易丢、对不上账。

**示例(朝钢 中联发)**:
- 港口现剩**约 90 吨**尾货。
- 因为火车一车(C70 车型)只能装 70 吨左右,所以每次发运会剩约 20 吨在某个货位上,累积成现在的尾货量。

## 2. 需求

给敞车装车项目建一个**港口尾货台账**,记录每个批次/每条船货物在**当前批次发运完毕后**,港口剩余尾货的处置情况:

- 台账单位:`(项目, 船名/批次, 货物品名)`。
- **触发**:批次发运完毕(`all_loaded` / `confirmed_received` 节点)时,提示/自动登记一条尾货记录;也支持人工录入与更新。
- **可更新**:尾货后续被清走 / 并入下一批 / 计损时,更新其状态与去向。

### 建议字段
| 字段 | 说明 |
|---|---|
| project / ship_name / release_batch_id | 归属项目、船、批次 |
| cargo_name | 货物品名 |
| remaining_tons | 港口剩余尾货吨数(如 中联发 ≈ 90) |
| yard_location / 货位 | 尾货所在货位 |
| disposition_status | 处置状态:留存 / 转入下批 / 计损 / 已清空 |
| disposition_note | 去向 / 备注(转入哪个批次、谁经手等) |
| recorded_at / updated_at | 记录与更新时间 |

## 3. 适用范围

- **适用**:敞车/散装整车项目 —— **中唐特钢、朝阳钢铁**。
- **不适用**:吉林金钢(集装箱业务,按箱不产生这种整车零头尾货)。
- 九三大豆散粮另有循环/池子台账,归循环运输会话,不在本工单内(如确需统一口径可后续合并讨论)。

## 4. 实现建议(供开发会话)

- 新表 `port_tail_cargo_ledger`(或类似),外键关联 `release_batches`。
- 尾货量口径参考:**船海关放行单总吨(出港计划通知单 special_matter 里的"海关放行单 XXX 吨")− 该船已整车发运吨数(95306/wagon shipped_weight 合计)= 港口剩余**。可作自动初值,人工可校正。
- 入口:CLI 录入/查询 + 看板展示(`scripts/cli_dashboard.py` 加一块尾货视图);批次走到 `all_loaded`/完毕时在报告里提示"请登记/更新港口尾货"。
- 与 [[release-batch-business-rules]]、朝钢 `shipped_weight_rule`(标载→实装映射)联动:尾货 = 到货总量 − Σ实装。
