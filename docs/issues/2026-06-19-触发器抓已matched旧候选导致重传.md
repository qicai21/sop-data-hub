# 问题:检装车文本触发器 rendezvous 抓到「已 matched 的旧候选」→ 重复跑链 + 重传鞍钢

- **发现日期**:2026-06-19
- **发现场景**:中联发 06-19 发车(44车)的触发器 #360,03:16 错挂到 06-16 的旧候选 `8d6b297`(image 3663,状态仍 `matched`),把 06-16 那列 53 车**重新跑链、重传鞍钢** → 鞍钢中联发 202 变 255(多 06-16 重复 53)。已人工删除那 53。
- **严重度**:中高 —— 会**重复对外上传鞍钢**,且每次同船发车都可能复发。

## 根因
`_execute_inspection_text_trigger`(workflow_task_executor.py ~618-629)候选查询:
`WHERE ship_name=? AND candidate_status NOT IN (_INACTIVE_CANDIDATE_STATUSES) ORDER BY created_at DESC LIMIT 1`。
- `_INACTIVE_CANDIDATE_STATUSES` **不含 `matched`** → 已处理/已上传过的旧候选仍算"活跃" → 被当成本次发车的候选抓出来重跑。
- 没有**日期就近校验**:06-19 的发车抓到 06-16 的候选也不拦。

## 期望修复
1. 候选 rendezvous **排除 `matched`**(已上传完成的不该再被委托);只认等待处理的(candidate / pending_*)。
2. 加**日期就近**护栏:候选 created_at 与触发器(发车)时间相差超阈值(如 >24h)不匹配,避免跨天错挂。
3. 回归:确保正常当天 rendezvous 不受影响;补一条"旧 matched 候选不被重抓"的守门测试。
