# 工单:中唐宝丽发运入库后仍停 enriched

- 日期:2026-07-06
- 项目:中唐特钢
- 船名:宝丽
- 类型:缺陷修复 / 生命周期推进
- 状态:已修复

## 背景

宝丽 lot01 已多次发运并完成 `wagon_shipments` 入库,但 `release_batches.dispatch_status`
仍停留在 `enriched`。看板上表现为“已有大量发运事实,批次仍像只补齐货运信息、未进入发运中”。

## 已核实事实

- `release_batch_id=942a5aec6b12c47cf96d12ce02f31d506ceaaeaf`
- `actual_wagon_count=144`
- `shipped_weight_tons=9788.6`
- `remaining_weight_tons=211.4`
- 当前车列:
  - `gqz2607041`:53 车
  - `gqz2607042`:53 车
  - `gqz2607051`:38 车
- 原生命周期日志只有 `pending_freight -> enriched`,没有 `enriched -> loading`。

## 根因

中唐检装车链路完成 95306 查票、`wagon_shipments` 入库和发运重量重算后,没有调用
`advance_lifecycle(..., "loading")`。

通用发运 executor 有“首票入库后推进 loading”的动作,但中唐/朝钢检装车链路是独立实现,
只在 `shipped_is_completed` 模式下处理朝钢式关单,漏掉了中唐这种
`full_track_to_received` 项目的 loading 推进。

## 修复要求

1. 本次车列票据已全部入库,且批次不再是 `pending_freight` 后,自动推进到 `loading`。
2. 推进必须使用 `advance_lifecycle`,依赖其幂等和非法回退保护。
3. `pending_freight` 批次仍只入库并挂 `pending_freight_info`,不能绕过货运信息闸去制表发送。
4. 增加回归测试:中唐批次从 `enriched` 经过检装车入库后必须推进到 `loading`;已在更后状态时不得回退。
5. 修复后重启使用该代码的服务。

## 当前处理

- 已手工将宝丽 lot01 从 `enriched` 补推进到 `loading`:
  - 原因:`宝丽已有144车入库,剩余211.4吨,补推进到loading`
  - 触发者:`manual.audit.baoli_enriched_after_wagons`

## 修复记录

- `workflow_task_executor` 在中唐/朝钢检装车链完成车列事实入库、通过 95306 全量闸并重算发运重量后,
  调用 `_advance_loading_after_wagon_ingest`。
- `_advance_loading_after_wagon_ingest` 使用 `advance_lifecycle(..., "loading")`,
  保留状态机幂等和非法回退保护。
- 输出 JSON 的 `lifecycle.loading_advance` 会记录本次推进结果,方便后续审计。
