# 工单：R0 规则总线与入口矩阵测试

- **提出日期**：2026-07-19
- **状态**：处理中
- **来源**：7 月主题×项目全表 + 评审审计；宝丽优先三连补丁；马兰希望 lot5 满量靠人工
- **范围**：放货批次匹配 / 候选推断 / 可接装判定；**不**重发 Excel、**不**重传门户

## 现象

1. 同船多 lot 的「显式 priority」曾只接到 `match_release_batch`，次日才补到 `infer_candidate_context`（打地鼠）。
2. `all_loaded` 批次不应再接新发运；匹配 open 集虽已是 `loading|enriched`，缺回归夹住。
3. 满量/计划箱数达上限后无统一闸门，依赖人工改 `all_loaded` + 完成 match rule。

## 目标

1. **规则单点**：多 lot 解析继续以 `match_release_batch_by_ship_destination_cargo` 为权威；推断同分必须调用它（已有，补矩阵测）。
2. **入口矩阵测试**：同一 fixture 覆盖 match 主链 + infer 同分路径；夹住：
   - 唯一最小 priority → 命中
   - 无 priority / 同 priority → `multiple_candidates` / pending
   - `all_loaded` 批次永不入选
   - match rule `completed` 不参与
3. **满量闸（最小）**：若存在 active `release_batch_dispatch_plan` 且 `allocated_box_count >= planned_box_count`，该 lot 不再作为 open 候选（与「满了改 all_loaded」业务一致，防漏改状态）。

## 非目标

- 实装/排车 OCR 语义大修
- 朝钢串旧趟 / 半窗
- 费用域
- 自动重发/重传

## 验收

- 新增/调整 pytest 全绿
- 不改生产业务数据（本工单只动代码+测试）
- 工单结案并归档
