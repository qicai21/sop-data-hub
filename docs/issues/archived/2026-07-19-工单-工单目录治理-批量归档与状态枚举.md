## 现象

审计（`docs/2026-07-19-评审-sop-data-hub工单与自动化审计.md`）指出：

- 大量 **claimed_done**（已处理/已完成/已修复）仍堆在 `docs/issues/` **根目录**
- 与 README「处理完即 `archived/`」严重不符
- 状态词不统一 → 扫目录像「问题山」，无法用目录当风险看板

治理前约：**根 98 / archived 23**。

## 处理

### 1. 批量归档（`git mv` → `archived/`）

本轮 **84** 份已闭环工单移入 `docs/issues/archived/`（含此前无正式状态行、但正文已结案的执行类工单，如中唐发货人回填、空头票闭环、吉林 33 车串趟等）。

**不归档**（仍留根目录）仅未闭环：

| 状态 | 数量（约） | 例子 |
| --- | ---: | --- |
| 待处理 | 5 | 事件唯一键审查、看板列宽、发运群收口、batch_key 更正、汐子 OCR JSON |
| 部分完成 | 6 | 散粮 sync、发车识别、环球信任尾巴、95306 lifecycle 设计收口等 |
| 暂缓 | 3 | 港口尾货台账、检装号核对未部署、wagon 入库主权评估 |

根目录工单数：**14**（+ README）。archived 合计约 **107**。

### 2. 状态枚举统一

写入 `docs/issues/README.md`：

| 状态 | 目录 |
| --- | --- |
| 待处理 / 进行中 / 部分完成 / 暂缓 / 待设计 | 根 |
| 已完成 / 已取消 | archived/ |

废弃同义词：`已处理`、`已修复`、长句状态等 → 新单只用枚举；`archived/` 即视为已完成。

14 份活跃工单标题下状态行已归一到上表。

### 3. 自检

```bash
ls docs/issues/*.md | grep -v README   # 应只有未闭环
rg -n '状态[：:].*已处理' docs/issues/*.md  # 根目录应无 claimed_done 冒充活跃
```
