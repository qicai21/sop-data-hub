# 工单：检装车文本到站分段识别与跨站隔离

- 日期：2026-07-30
- 涉及项目：中唐特钢、朝阳钢铁（同时保护非 SOP 流向）
- 状态：已完成

## 现象

铁晟业务工作群的发运文本可在同一条消息中同时包含多个到站、船名与车数。例如：

`煤四，53节汐子铁宝丽，3节乌铁春日莲花`

现有 `inspection_text_trigger` 只按已知船名切段，并将命中的船名直接赋为
项目默认到站；它不识别文本内的到站段。因此宝丽错误继承了随后“乌铁春日莲花”
的 3 节，生成“宝丽/汐子/3 节”触发器。

`凌东`、`凌源东`、`乌铁`、`乌兰浩特`均未参与该触发器的到站解析；写成全称不能
消除误触发。

## 目标

1. 从 2026-07 铁晟业务工作群提取带车数和到站信号的文本，按归一化形态去重，形成
   受版本管理的语料基线及典型样本。
2. 新建文本到站分段识别器：先规范化别名、识别跨站边界，再在各站段内匹配船名与车数。
3. SOP 触发器只接受“站点归属与项目一致”的段；非 SOP 站点只能作为隔离边界，绝不让
   其数量被相邻 SOP 船名继承。
4. 兼容数量前置/后置、逗号空格变体、`汐子/沙子` 等已知容错；未知站名或缺少明确
   站点时不猜测，保留原有船名兜底仅用于单站、无冲突文本。
5. 为真实历史形态建立稳定测试，并回归既有检装车文本触发器测试。

## 验收标准

- `汐子宝丽53节 + 乌铁春日莲花3节` 仅生成宝丽 53 节汐子触发器。
- `凌东铁宝腾海51节` 可被归一为凌源东非 SOP 段，不生成朝阳西触发器。
- `朝阳西铁宝腾海51节` 正常生成朝钢 51 节触发器。
- 单站文本（如 `煤四 汐子铁 宝丽53节`）保持现有行为。
- 全量测试通过；修改后重启 `text-watch`。
