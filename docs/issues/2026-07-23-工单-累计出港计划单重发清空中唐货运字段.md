# 工单：累计出港计划单重发清空中唐货运字段

- **日期**：2026-07-23
- **状态**：已完成
- **项目**：中唐特钢

## 现象

宝丽第五次出港计划通知单已创建 `lot05`，随后 `中唐特钢发运群`
于 16:15:06 收到完整货运文本：

- 货物品名：麦克粉
- 数量：10000 吨
- 计划号：`90260700073`
- 合同号：`ZLZT-2026072101`

消息被记录为 `task_succeeded`，但 `lot05` 仍为 `pending_freight`。

## 根因

累计出港计划通知单会重带历史 lot。`release_batches` 的冲突更新逻辑
直接使用通知单解析结果覆盖 `contract_no`、`plan_id`、`order_id`。通知单
本身没有这些货运字段，导致已经补齐的宝丽 `lot04` 被空值清除。

此时宝丽 `lot04`、`lot05` 同时缺计划号，今天的货运文本触发“同船多个
在途批次缺计划号”歧义保护，没有写入任何批次；歧义分支又被记为任务成功。

## 修复

1. 出港计划通知单重发时，空值不得覆盖已有合同、计划、订单和货物品名。
2. 恢复宝丽 `lot04` 已确认的货运字段。
3. 将 16:15:06 的货运文本绑定宝丽 `lot05`，推进到 `enriched`。
4. 回写消息和任务的真实处理结果，保留审计记录。
5. 添加累计通知单重发不清空货运字段的固定回归测试。

## 验收

- 宝丽 `lot04` 保留 `90260700052 / ZLZT-2026071401 / 麦克粉`。
- 宝丽 `lot05` 写入 `90260700073 / ZLZT-2026072101 / 麦克粉 / 10000吨`。
- 看板“挂起出港计划通知单”归零。
- 通知单再次重放后，两个批次货运字段不被清空。
