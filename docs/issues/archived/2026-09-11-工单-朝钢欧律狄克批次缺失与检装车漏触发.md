# 工单：朝钢欧律狄克批次缺失与检装车漏触发

- **日期**：2026-09-11
- **状态**：已完成
- **范围**：朝阳钢铁 / 出港计划通知单 / 检装车文本触发 / 历史数据修复
- **theme**：T4_挂起

## 现象

欧律狄克实际存在三次铁路放货：`lot01=7500吨`、`lot02=2500吨`、
`lot03=20000吨`。系统只保留了一个错误日期的 lot01，并把前三列共 157 车
全部归入该批次；2026-09-07 的 55 车和 2026-09-10 的 53 车均已在 95306
制票、交付，但未进入 `wagon_shipments`，两张检装车通知单停在
`pending_review`。

## 根因

1. `chaoyang.yaml` 的 `project_meta.known_ships` 缺少“欧律狄克”。发车文本
   因此未进入 `inspection_text_trigger_flow`，而误落到朝钢未声明执行器的
   普通 `departure_flow`，没有生成 workflow task。
2. 2026-09-04 累计出港计划通知单已识别出欧律狄克和三次计划，但未知船名闸
   返回 0 条，导致 lot02、lot03 未创建。
3. 人工先建的 lot01 日期为 2026-08-21；原始通知单明确三次计划日期分别为
   2026-08-14、2026-08-21、2026-09-04，需要按原图纠正并重排车辆。
4. 9月7日通知单页脚明确“实装55节”，但 VLM 将一辆“车皮破损”车仍标为
   非缺陷，候选计成56车；文本会合只比较 `wagon_count`，因此无法进入后续
   95306 权威集合校正。

## 修复

1. 将“欧律狄克”加入朝钢已知船名，并增加真实文本回归测试。
2. 文本与图片候选会合时，允许页脚“实装节数”作为计数锚点；会合后仍由
   95306 车号集合完成最终剔除，不能仅截断通知单末尾车辆。
3. 按原始通知单和用户确认创建三个独立 release batch；已知货运字段沿用现有
   欧律狄克信息，未知合同号保持空值，不编造。
4. 按制票先后顺序重新分配既有车辆：先填满 lot01，再填 lot02，余量进入
   lot03；随后处理 9月7日、9月10日两张候选。
5. 备份数据库，核对 `ydid` 唯一性、每列车数、批次重量、候选终态、Excel、
   鞍钢门户上传及微信发送结果。
6. 累计通知单去重时，`total_planned_quantity` 在过滤已入库 lot 之前计算，
   避免只统计本次新建的 lot。本例三批累计值均为 `30000`。
7. 按候选车组补生 Excel 时，文件日期改为取本次导出行的制票日，
   不再取整个 batch 的最新制票日。

## 验收

- “煤四朝阳西欧律狄克53节”路由为 `inspection_text_trigger_flow`。
- release batch 恰为 lot01/lot02/lot03，数量分别为 7500/2500/20000 吨。
- 8月23日至9月10日对应欧律狄克的 265 个 95306 `ydid` 在
  `wagon_shipments` 中不多不少且只归属一个 lot。
- 两个 `pending_review` 候选均消除，按实际列分别生成/发送 Excel，并核验
  鞍钢门户数据。
