## 3. 根因（结构层，不单是「一次配错」）

1. **满量 / 箱数上限未强制**  
   - lot05 计划 10000t（约 310 箱量级），但系统无「到 234 箱必须停」的硬闸。  
   - `release_batch_dispatch_plan` 对 lot05/06 **未配置** `planned_box_count`。  

2. **双 active 同优先级**  
   - lot05、lot06 的 `release_dispatch_match_rules` 均为 `active` 且 **priority=100**。  
   - 中唐式「唯一最小 priority 才自动选」在此 **无法区分** → 新车继续贴 loading 的 lot05 是「自然结果」。  

3. **lot06 建批后未切换写入目标**  
   - lot06 于 07-16 已 `enriched`，但 07-16 当天 184 箱仍写入 lot05（符合当时「lot05 填 234」）；  
   - **07-18 在 lot05 已满 234 后仍写入 lot05**，说明 **满量切换逻辑缺失**。  

4. **历史分票债**  
   - 工单已明确：吉林以 `wagon_container_shipments` 为唯一事实源；旧 `wagon_shipments` 冻结。  
   - lot05/06 车级表为 0 行（符合新路径）；lot04 车级仍有 226 行 vs 箱级 154 车，**旧债仍在**，本次方案 **不强制清理 lot04 车级**。  

5. **对外已按错误 lot 出过单（风险）**  
   - 2026-07-18：`generate_shipping_excel` / `send_shipping_excel_wechat` / `factory_upload_submit` 均 **executed**，idempotency 键绑定 **lot05 的 batch_id**（`1a5893ded730…`）。  
   - 即：7-18 的 46 车 Excel/上传 **已经以 lot05 名义发出**。改库后看板会变对，但 **客户侧单据 lot 号可能与库不一致**，需你决定是否更正门户/是否重发（你方数据单发群可隔离微信风险，**门户不一定**）。
