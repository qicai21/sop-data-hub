# 追溯工单:VLM 从 qwen3-vl 迁移至 Qwen3.6-35B@8021

- **类型**:模型服务迁移 / 追溯补录
- **发生日期**:2026-06-26
- **补录日期**:2026-07-01
- **状态**:已处理
- **严重度**:高

## 背景

2026-06-26 对本项目 VLM 路线做了较大调整:从旧 `qwen3-vl`/旧 `VL-8B@8018` 路线,切换为本机 `Qwen3.6-35B-A3B-4bit` 单模型服务,通过 `mlx_vlm.server` 的 OpenAI 兼容 `/v1/chat/completions` 接口提供能力,端口为 `8021`。

迁移目标:

- 检装车通知单识别与抽取统一走 35B。
- 出港计划通知单识别与抽取统一走 35B。
- 微信群图片分类统一走 35B。
- 旧 `8018 /generate` 自定义协议退出现网主链,仅在兼容分支中保留。

本次迁移当时有 git 提交记录,但未建立独立 `docs/issues/` 工单,不符合当前项目协作规则。此工单为追溯补录。

## 关联提交

- `1868381 fix(vlm): 全迁单模型35B@8021,修迁移漏改yaml致抽取仍打死端口8018`

## 主要变更范围

- `src/sop_hub/vlm_client.py`
  - 新增统一 VLM 调用入口,按 URL 自动适配:
    - `/v1` OpenAI 兼容协议:base64 图片 + `chat/completions`。
    - 旧 `/generate` 协议:本地 `image_path` 方式,作为兼容兜底。
- `src/sop_hub/config.py`
  - 默认 VLM 服务切到 `http://127.0.0.1:8021/v1/chat/completions`。
  - `vlm_openai_model` / `classifier_openai_model` 指向 `/Users/qicai21/models/Qwen3.6-35B-A3B-4bit`。
- `config/settings.yaml`
  - 修正迁移漏项,确保运行配置不再打旧 `8018`。
- `src/sop_hub/classifier/classifier.py`
  - 分类器迁移到 35B OpenAI 兼容端点。
  - 图片分类对外收敛为 4 类:检装车通知单、出港计划通知单、其他业务图片、现场作业照片。
- 抽取引擎:
  - `src/sop_hub/engines/inspection_slip.py`
  - `src/sop_hub/engines/departure_plan.py`
  - `src/sop_hub/engines/handwritten_list.py`
  - `src/sop_hub/engines/materials_stats.py`
  - 统一切到 35B@8021 路线。
- CLI / runner / pipeline:
  - 默认服务地址、模型字段和测试期望同步更新。

## 风险与后续

- 35B 模型在 32G Mac Studio 上能力更强,但资源压力明显高于旧 8B 路线。
- 2026-07-01 复盘发现 `mlx-vlm 0.6.3` + `Qwen3.6-35B-A3B-4bit` 在 `temperature == 0` 的 greedy fast path 下,长批量运行可能触发 Metal threadgroup 限制。
- 该稳定性问题已由后续工单处理:
  - `2026-07-01-工单-qwen35b-mlx-vlm-greedy路径不稳定优化.md`

## 验收口径

- 主链配置默认打 `8021 /v1/chat/completions`。
- 分类器、检装车抽取、出港计划抽取均使用 `Qwen3.6-35B-A3B-4bit`。
- 旧 `8018` 不再作为现网主链入口。
- 迁移后出现的服务稳定性问题另立工单跟踪,不混入本追溯工单。
