## 一、现象

`cli_dashboard.py` 主看板嵌入的「箱循环流水线」(`jiusan_cycle_board.render_lines()`)中:
`港重 / 途重(在途重) / 返空` 三个节点的箱数不对或显示 0。修复前实际渲染:`港重154 · 途重0 · 返空29`。

## 二、根因(定位到字段/函数/行)

**① 途重(在途重)恒为 0 —— 数据层 parse bug**
`scripts/jiusan_morning_report_ingest.py::parse_report`(原 line 84):
```python
transit_cars = _num(r"在途\s*(\d+)\s*节集装箱", text)
```
晨报在途行措辞有两种:历史 6/12「在途50节**集装箱**」、6/29「在途40节**重箱**」。正则只认「集装箱」→ 6/29 漏配 → `transit_loaded=0`(实际应 40节×2=80箱)。`auto_morning_report` 自 6/24 起每天途重=0,与之前人工 `field` 行(6/23=88、6/19=100)对照即坐实。

**② 返空漏算 + 锁死单船 —— 95306 逻辑 bug**
`scripts/jiusan_cycle_board.py::_cycle_positions`(原 line 104-107):
```python
for cyc, deliv, boxes in delivered[1:]:
    pos["transit_empty"] = {"cyc": cyc, "boxes": boxes}   # 循环里被覆盖,中间列被丢
```
- 覆盖 bug:多列已交付时,`transit_empty` 每轮覆盖只剩最后一列,中间列(6/29 的 cyc2=100 箱)既不算港重也不算返空,凭空消失。
- 锁死单船:查询 `WHERE batch_id=_CBATCH`(和谐1 集装箱 batch)。但**和谐1 已于 6/25 末次发车,当前在跑的是诚信**(诚信 6/28 仍发车,且 180 车里 140 命中 jiusan 车体池 = 复用同一组循环列)。`_cycle_positions` 只看和谐1 旧趟、看不到诚信新趟 → 循环列状态停在旧船,港重 #列/返空全错。

**③ 看板口径锚在单船 和谐1 —— 与业务不符**
晨报「剩余重箱」本就是**锦州港集装箱总量**(6/25「105箱(29和谐1，76诚信)」即港总池拆注),但看板标题/快照 key 写死「和谐1」。用户明确:这套循环看板是**九三大豆项目整体**口径(通常一船发完发下一船,也有 2–3 船混发),应改为「锦州港集装箱总池」,不拘单船。

## 三、改动

### 1. `scripts/jiusan_morning_report_ingest.py`
- `parse_report` 在途正则 → `在途\s*(\d+)\s*节\s*(?:集装箱|重箱)`,兼容两种措辞;「散粮车」「在途无」仍不计。

### 2. `scripts/jiusan_cycle_board.py`(核心)
- 新增 `_col_latest_trips(conn)`:**总池口径**,去掉 `batch_id=_CBATCH` 过滤,仅以 `JOIN wagon_body_pool(project=jiusan)` 按车体识别循环列,取每列**跨船最近一趟**(诚信新趟自动盖过和谐1旧趟)。
- 新增 `_cycle_state(conn, now)`:返空状态机(用户铁律 §返空 规则 1/2/3):
  - 已发未到 → 途重;已到站·部分交付 → 新台子(绝不计返空);
  - 已到站·全部交付:末交付 >5h(`RETURN_HOME_HOURS`)**或** 已有更新进站列开卸 → 返空回港(最早交付=在装列港重);否则 → 返空在途;
  - 部分交付拖长 + 有更新进站列开卸 → 挂**人工确认**(规则 3:是否主体已返空、少量车随下趟返港)。
  - `transit_empty_boxes` = 所有返空在途列箱数**之和**(根治覆盖 bug)。
- `_cycle_positions` 改为 `_cycle_state` 的 back-compat 包装(返回 pos 映射,transit_empty.boxes 为和)。
- `render_lines`:返空数改取 `_cycle_state` **实时**值(95306 原生,不再读易停在旧值的 snapshot.transit_empty);标题/图例口径 → `DISPLAY="九三大豆·锦州港集装箱总池"`;规则 3 的确认项在图例下醒目挂出。
- `_hours_since` 容错 `HH:MM` 与 `HH:MM:SS` 两种时间戳。
