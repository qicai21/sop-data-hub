# 工单:九三晨报表头日期误写导致当日快照跳过

- 日期:2026-07-06
- 项目:九三大豆
- 类型:缺陷修复 / 晨报对账
- 状态:已修复

## 背景

2026-07-06 早上九三大豆发运群已有晨报,但循环看板没有生成 2026-07-06 的
`container_pool_snapshot` 快照。

## 已核实事实

- `jiusan-morning-ingest` launchd 定时任务存在,配置为 8:00 / 9:00 / 10:00 / 11:00 执行。
- 2026-07-06 09:00 日志仍在处理:
  - `晨报截止5日 → 快照 2026-07-05`
  - `快照 2026-07-05 已存在 → 跳过`
- GROUP093 最新晨报消息时间为 `2026-07-06 07:11:21`,正文表头仍写:
  - `截止5日早7点(阴)`
- 该正文内容已经是新晨报:
  - 昨日装箱 7 箱,发运 80 箱
  - 港内剩余重箱 60 箱
  - 可用空箱 291
  - 新台子 80 箱
  - 330 落地重箱 77 箱

## 根因

`scripts/jiusan_morning_report_ingest.py` 完全信任正文的 `截止N日`,并用它拼出
`snapshot_date`。当人工晨报表头日号忘记从 5 改为 6 时,脚本把 7月6日晨报误认为
7月5日晨报,又因 7月5日快照已存在而幂等跳过。

## 修复要求

1. 正常情况下仍按正文 `截止N日` 生成快照日期。
2. 若微信消息发送日期与正文截止日号不一致,采用微信消息发送日期作为快照日期。
3. 将表头日期不一致写入快照 note,便于后续审计。
4. 补录 2026-07-06 晨报快照。
5. 增加回归测试。

## 处理记录

- `pull_latest_morning_report` 增加微信消息发送日期返回值。
- 新增 `resolve_snapshot_date`:
  - 正常表头:仍按 `截止N日` 记账。
  - 表头日号与微信发送日期不一致:按微信发送日期记账,并生成审计说明。
- 已补录 2026-07-06 快照:
