# 工单:检装车错号纠错未覆盖排车混合场景

- **类型**:检装车 95306 核对纠错规则补强
- **发现日期**:2026-07-01
- **状态**:已处理
- **严重度**:高

## 背景

马兰幸福 `wx_2026-06_2351` 检装车通知单仍挂 `pending_review`。人工核对发现:

- 通知单车号 `1591601` 应为 `1891601`。
- 95306 窗口内有 `1891601`。
- 通知单另有 `1891573`、`1891581` 两个排车,不应阻断错号自动纠正。

当前核对结果:

```text
通知单车号数: 55
95306 窗口车数: 53
交集: 52
通知单有、95306 没有: 1591601, 1891573, 1891581
95306 有、通知单没有: 1891601
```

## 根因

已有工单 `2026-06-29-工单-检装车号95306自动核对纠错.md` 已实现自动纠错,但保守条件为:

```text
notice_only 数量 == window_only 数量
```

该条件只覆盖“所有 notice_only 都是错号”的案例。马兰幸福本次是“真排车 + 单个错号”混合场景:

- `notice_only` 包含 2 个真排车 + 1 个错号。
- `window_only` 只有 1 个 95306 真号。

因此自动纠错函数整体返回空,候选继续挂 `pending_review`。

## 处理原则

- 对每个 `window_only` 异常车,在 `notice_only` 中找唯一近似错号。
- 所有 `window_only` 都能唯一配对时,执行纠错。
- 未配对的 `notice_only` 保留为真排车,不阻断放行。
- 任一 `window_only` 找不到唯一错号、配对非单射、超过最大纠错对数时,仍挂人工。

## 验收标准

- `1591601 -> 1891601` 可自动纠错。
- `1891573`、`1891581` 保留为排车。
- 纠错后 `missing_from_notice=[]`,状态为 `ok`。
- 既有“多异常但只有一个错号、仍有无法解释异常”的用例继续保持 `anomaly`。

## 处理记录

代码改动:

- `src/sop_hub/sop/inspection_window_recover.py`
  - `_autocorrect_notice_car_numbers()` 从原来的 `notice_only 数量 == window_only 数量` 改为按 `window_only` 逐个解释异常车。
  - 每个 `window_only` 必须在 `notice_only` 中找到唯一最小距离近似错号。
  - 未配对的 `notice_only` 保留为真排车。
  - 若最小距离并列、找不到近似、配对非单射或超过 `max_pairs`,仍返回空,维持人工复核。
- `tests/functional/test_inspection_window_recover.py`
  - 新增“排车 + 单个错号混合”用例。
  - 保留“仍有无法解释 window_only 异常车 → anomaly”用例。
