# 工单：Slack 受控 SOP 单事件路由

- **日期**：2026-09-22
- **状态**：实现完成，等待 Slack 业务确认
- **范围**：中唐特钢中联发 31 车候选、SOP 单事件 Adapter、Slack Gateway

## 现象

Slack 已只读定位中联发 31 车（候选 `wx_2026-09_2033`），但候选虽然关联
`lot02`，到站和货名为空，工作流任务 `1171` 跳过；Slack Gateway 又要求用户
手输内部 ID，无法在同一线程完成受控预检和确认。

## 根因

`infer_candidate_context` 的文本融合分支沿用旧生命周期
`in_progress/suspended` 筛选；当前货运补齐后的可接检装批次为 `enriched`，被错误排除。
Gateway 目前没有持久化 preflight，也没有受限单事件入口。

## 修复计划

1. 让文本融合与正式开放状态集一致，并以 fixture 回放中联发的 enriched lot。
2. 在 SOP 提供固定 cwd 的 preflight/execute 契约：只允许已定位的单事件，禁止
   `run_pending`/`force`，执行前后校验 YDID、事件 Excel、外部动作与发送证据。
3. Gateway 持久化线程/用户绑定的 preflight 摘要、digest 和 TTL；同线程的明确确认
   才能调用 SOP 单事件 Adapter。

生产 `wx_2026-09_2033` / 任务 `1171` 不在本工单开发阶段执行；待实现、回放和
Slack 确认完成后再由用户发最终业务确认。

## 实施结果

1. `infer_candidate_context` 文本融合已使用正式开放状态
   `pending_freight/enriched/loading`；回放证明 enriched lot 能完整保留项目、船、到站、
   货名和批次上下文。
2. 新增 `slack_single_event_adapter.py` 与 JSON CLI：preflight 全程只读，按正式执行器
   相同口径，以车号、到站、铁矿货名取每车最新 95306 货票；execute 校验 TTL 和
   preflight digest，先做时间戳备份，再仅调用一个 `run_workflow_task(id, force=False)`。
3. 完成条件不是 bridge 返回码：正式 Excel 必须存在，并且必须在 wx-ops-agent 的
   GROUP013（数据单发群）JSONL 中回读到同名、执行开始时间之后的真实 file 消息。
4. 单元/功能测试覆盖：跨日期最新货票、缺车、过期 token 在接触 DB 前拒绝、真实附件
   类型和时间边界；仓库全量结果为 733 passed、1 skipped。
