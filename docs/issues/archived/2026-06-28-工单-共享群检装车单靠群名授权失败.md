## ✅ 开发处理结果(2026-06-28,commit fe08d0e)

**验证假设**:**部分对、部分错**。授权不是靠"群名"——`runner._infer_sop_project_token` 是**内容驱动**(搜 payload 文本里的硬锚:到站/项目名/船名)。真因:
- 检装车单硬锚列表只有 `汐子/鞍子河/中唐/赤峰中唐`,**到站"汐子"被 OCR 读成"沙子"** + 文本无"中唐"字样 → 全没命中 → 授权 False → 卡 classified。
- 船名"丰收散运"明明在 payload 里(且是中唐 yaml `known_ships`),但**那步没用 known_ships 消歧**。

**修复**:
1. `_infer_sop_project_token` 末尾加 **known_ships 唯一命中兜底**:硬锚没命中时,船名命中某项目 yaml `known_ships`(各项目互不重叠)即唯一定位授权;多项目同时命中不强授(交人工)。**坑**:`_active_project_sop_tokens` 同时返回项目 key + 中文显示名,只数 ascii key 否则同项目数两次 → 永不唯一。

## 现象

中唐 丰收散运 **60车** 检装车单(message wx_2026-06_2112,json `474_f5eaf6ba...`,2026-06-28 03:44 到,60装1排),`processing_status=classified` 不前进,没生成检装车候选。

对照:同内容若发在 **中唐特钢发运群** 则正常(wx_2026-06_62 / 32_b1b26f 建了候选);60车这张发在 **铁晟业务工作群**(吉林/朝钢/中唐/金通共享)。

## 根因

检装车通知单的项目授权(`_agent_sop_authorized`)**主要靠群名 → 项目** 的映射:
- 中唐特钢发运群 → 唯一 zhongtang → 授权=True。
- 铁晟业务工作群 = 多项目共享 → 推不出唯一项目 → 授权=False → `image_route_promoter`(line 45 `_agent_sop_authorized is False` 跳过)不建候选。

船名"丰收散运" + 到站"汐子"本可唯一定位 zhongtang(丰收散运是中唐 known_ship、汐子是中唐到站),但**授权那步没用船名/到站消歧**;且 OCR 把"汐子"读成"沙子"(cargo_summary 里是"沙子铁矿粉"),归一也没接到这一步。

## 期望 / 建议

- 共享群的检装车单,群名推不出项目时,**回退用船名(命中某项目 known_ships)+ 到站(命中某项目 destination)消歧授权**,唯一命中即授权该项目。
- "沙子/夕子→汐子" 等到站归一([[ocr_normalize_shipper_station]] 的闭集)接到检装车项目推断这一步。
- 推不出时不要静默停 classified,应挂 pending_review 或告警,便于人工接管。
