# 工单：吉林箱级重分票未重算看板重量

## 现象

蓝鳍 `lot11` 已有 154 箱 / 77 票，但货运看板仍显示旧的 84 箱折算重量
`2,711.52` 吨；吉林金钢项目配置为每箱 `32.28` 吨，正确已发重量应为
`4,971.12` 吨。

## 根因

`allocate_container_ydids()` 在按分票计划更新
`wagon_container_shipments.batch_id` 后，只刷新了
`release_batch_dispatch_plan.allocated_box_count`。货运看板读取的
`release_batches.shipped_weight_tons` / `remaining_weight_tons` 没有同步重算，
因此继续展示分票前的汇总快照。

## 修复范围

1. 箱级分票成功提交后，收集实际发生归属变更的 lot。
2. 对这些 lot 调用统一的 `compute_for_release_batch()`，由项目 YAML 的
   `shipped_weight_rule` 重算重量、剩余量与实际车次。
3. 增加功能测试：分票后批次重量必须按箱级事实更新，而不依赖旧值。

## 验收

- 蓝鳍 `lot11` 为 154 箱 / 77 票 / `4,971.12` 吨 / 剩余 `28.88` 吨。
- 后续吉林金钢自动分票后，看板重量无需人工重算即可更新。

## 状态

已完成。
