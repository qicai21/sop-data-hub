# 工单：评估 wagon / wagon-container shipment 入库主权归一机制

创建日期：2026-07-04
项目：全 SOP 项目
状态：下个版本评估；暂不实施
优先级：P2 设计评估

## 背景

当前 `wagon_shipments` / `wagon_container_shipments` 的入库触发来源较多：

- 微信文本消息经 `text-watch` 触发检装车/发车链路；
- 检装车通知单图片识别后建立候选并触发链路；
- `rail95306-sync` 更新 95306 事实库后，再由 verifier / reconcile 等机制补齐挂起候选；
- 不同项目还有内部群发车文本、放货批次、货运信息闸等项目级约束。

实际运行中多次出现“文本触发”和“检装车图片触发”抢同一批业务事件的问题：一方先触发但票未齐、另一方后触发或补齐，随后系统要通过 pending / verifier / reconcile / 人工补偿继续“收拾残局”。这造成挂起状态多、状态解释困难，也容易出现 Excel 发送、收货人上传、看板状态之间不同步。

## 初步思路

考虑将入库主权从“微信消息触发链路”调整为“95306 制单事实驱动”：

1. 微信监听拿到的图片/文本/OCR JSON 只进入候选库，不直接作为最终 wagon 入库主触发。
2. SOP 项目持续追踪 95306 库更新。
3. 当 95306 中发现某个 SOP 项目有新的制单记录时，由系统主动到候选库中匹配相关微信候选数据。
4. 匹配成功后，以 95306 的 `ydid` / `hph` / 车号 / 箱号 / 制票时间等事实为主权，候选库只提供项目、船名、lot、道线、货物品名、人工备注等业务上下文。
5. 入库、发运 Excel、上传收货人系统等后置动作统一挂在“95306 新事实 + 候选匹配成功”的状态机之后。

这样可以让 wagon fact 的主权归一到 95306，减少 `text-watch` 与检装车通知单图片抢触发、重复触发、半套数据 pending 的问题。

## 需要权衡的问题

### 1. 95306 不是完整业务上下文

95306 能提供车/箱/运单事实，但不一定完整提供：

- SOP 项目归属；
- 船名 / lot / 合同号 / 计划号；
- 股道 / 道线；
- 放货批次状态；
- 检装车通知单里的排车、错号、人工备注；
- 集装箱每日发车文本中的道线归属。

因此“95306 主权”不能等于“只看 95306”。更合理的方向是：95306 负责事实入库触发和车箱事实权威，微信候选库负责业务上下文匹配。

### 2. 候选库匹配需要可解释

候选库应明确保存：

- 来源消息：群名、message_id、收到时间、图片/文本路径；
- OCR / VL 原始 JSON；
- 推断出的项目、船名、lot、目的站、货物、道线、预期车数/箱数；
- 人工修正后的权威字段，例如 `car_numbers_json`、`box_numbers_json`、道线、lot 分配；
- 匹配状态和未匹配原因。

匹配失败时应进入可解释状态，而不是把业务链路卡成模糊 pending。

### 3. 后置动作幂等边界要重新梳理

若触发主权改为 95306 更新，则需要重新定义后置动作幂等键：

- 发运 Excel：按项目 + release_batch_id 集合 + `ydid` 集合或车/箱事实集合；
- 微信发送：按同一业务事件/同一事实集合只发送一次；
- 收货人系统上传：按收货系统要求，通常按 `ydid` / 车号 / 箱号集合；
- 看板状态：按事实状态、候选匹配状态、后置动作状态分层展示。

### 4. 项目差异仍要保留

四个 SOP 项目规则不同：

- 中唐、朝钢、吉林金钢主要围绕检装车通知单、发运 Excel、收货人系统；
- 九三大豆同时有散粮车、集装箱、循环车组、内部群道线文本、每日对账等逻辑。

因此不能简单做一个通用“95306 新票即入库”。需要按项目声明匹配规则和后置动作。

## 建议下个版本调研/设计任务

1. 梳理现有所有 `wagon_shipments` / `wagon_container_shipments` 写入口：
   - 触发源；
   - 写入字段；
   - 幂等键；
   - 后置动作；
   - 失败/挂起状态。
2. 设计候选库规范：
   - 图片候选；
   - 文本候选；
   - 货运信息候选；
   - 人工修正候选；
   - 与 release_batch / 95306 fact 的匹配状态。
3. 设计 95306 更新驱动的匹配状态机：
   - `new_95306_fact_detected`;
   - `candidate_matched`;
   - `candidate_missing_context`;
   - `ambiguous_candidates`;
   - `ready_to_ingest`;
   - `ingested`;
   - `post_actions_done`;
   - `manual_review_required`。
4. 选择一个项目做试点：
   - 建议先用朝钢或中唐整车发运试点，因为车号/`ydid` 粒度清晰；
   - 九三集装箱和循环车组复杂度更高，适合第二阶段。
5. 输出迁移方案：
   - 哪些旧链路保留为候选采集；
   - 哪些旧链路停止直接入库；
   - 如何避免新旧机制并行期间重复入库/重复发送；
   - 如何回滚。
