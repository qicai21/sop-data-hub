## 3. 当前系统职责

- 系统不自动跟踪检装车通知单。
- 系统不自动识别或跟踪放货单。
- 用户发送放货单后，由用户或 agent 手动指认项目、路线、运输方式、批次信息和特殊说明。
- 系统需要基于 `xts` 账号的 95306 发车数据，实时更新九三大豆项目发运动态。
- 当前 SOP 是项目初始化版本；后续用户会补充更细的放货单格式、字段、报表、异常处理和状态看板要求。

## 4. 数据源与入口

| 来源 | 类型 | 当前用途 | 自动入业务链路 |
|---|---|---|---|
| 数据单发群（`[GROUP013]`） | 图片、文字、文件 | 接收用户手动发送的放货单、说明和补充材料；只归档并等待人工指认 | 否 |
| 95306 `xts` 账号 | 发车/运单数据 | 按项目规则查询每日发车数据，更新发运动态 | 是 |

说明：
- 群只表示材料入口，不代表项目归属。
- 放货单默认不因图片分类或文字关键词自动建批。
- 只有用户明确说明“这是九三大豆项目放货单/发运信息”后，agent 才能把材料接续到九三大豆项目。
- `xts` 账号数据是发运动态的事实来源；放货单是计划/批次设置来源。

## 5. 术语与业务锚点

| 术语 | 说明 |
|---|---|
| 铁路专用线 | 企业或其他单位管理、与国家铁路或其他铁路接轨的岔线；属性以 95306 官网公示为准 |
| 专用铁路 | 企业或其他单位管理，专为本单位内部提供运输服务的铁路；属性以 95306 官网公示为准 |
| 三三〇处专用线 | 新台子站下的铁路专用线，距离铁岭九三大豆厂约 3 公里；本项目集装箱货物基本在此卸车后汽车短倒进厂 |
| 九三集团铁岭大豆科技有限公司专用线 | 新台子站下的九三厂内专用线，只能卸散粮车/K车，一次约容纳 20 车 |
| 散粮车 / K车 | 大豆散粮车运输车辆，发往九三厂内专用线后直接入厂卸货 |
| 得胜台 | 新台子接卸能力不足时的补充到站，距九三工厂约 15 公里，平时不作为常规发运路线 |

## 6. 运输路线与价格

| 路线 | 运输方式 | 合同描述 | 业务定位 | 含税包干价 |
|---|---|---|---|---|
| A | 集装箱 | 货物装集装箱经铁路发往国家粮食和物资储备局辽宁局三三〇处专用线，并汽车倒运至九三工厂 | 常规集装箱路线 | 65.43 元/吨 |
| B | 铁路敞顶箱 | 货物铁路敞顶箱经铁路发往得胜台车站，并汽车倒运至九三工厂 | 新台子接卸能力不足时的补充路线 | 65.60 元/吨 |
| C | 散粮车/K车 | 货物装散粮车经铁路发往新台子站九三集团铁岭大豆科技有限公司专用线，直接入厂 | 常规散粮车路线 | 65.13 元/吨 |

路线规则：
- 主路线分为集装箱和散粮车/K车两类。
- 集装箱：`高桥镇 -> 新台子/三三〇处专用线 -> 汽运短倒至九三工厂`。
- 散粮车/K车：`高桥镇 -> 新台子/九三集团铁岭大豆科技有限公司专用线 -> 入厂直接卸货`。
- 得胜台为补充路线，仅在新台子站接卸能力不足时考虑；平时不发。
- SOP 和程序匹配时，不能把三三〇处专用线、九三专用线、得胜台简单合并为同一个目的地。

## 7. 节点定义

### 7.1 合同信息保存

| 字段 | 内容 |
|---|---|
| 输入 | 用户提供的合同文件 |
| 触发条件 | 用户要求建立九三大豆项目 |
| 处理动作 | 将合同文件保存到项目目录；抽取合同编号、主体、货物、路线、价格和有效期 |
| 输出 | 合同文件路径和合同要素 |
| 当前说明 | 现有 `contracts` 表为单价格模型，不适合一次性登记三条路线价格；本 SOP 先以文件和 SOP 条款为准 |

### 7.2 放货单人工指认

| 字段 | 内容 |
|---|---|
| 输入 | 用户发送的放货单图片、文件、文字说明 |
| 触发条件 | 用户明确指认该材料属于九三大豆项目 |
| 处理动作 | 归档原始材料；由 agent 根据用户说明设置放货批次、运输路线、预计数量、目的专用线/到站、运输方式 |
| 输出 | 待确认或已确认的放货发运信息 |
| 自动化边界 | 不自动跟踪放货单，不凭关键词自动建批 |
| 人工介入条件 | 放货单未指认项目、路线不清、集装箱/散粮车不清、目的专用线不清、得胜台启用原因不清 |

### 7.3 95306 每日发车数据同步

| 字段 | 内容 |
|---|---|
| 输入 | `xts` 账号下 95306 发车/运单数据 |
| 触发条件 | 95306 同步服务获取到新发车数据 |
| 处理动作 | 按起运站、到站/专用线、货物、收货人、运输方式识别九三大豆项目发运记录 |
| 输出 | 发运动态、已发车数、到站/专用线、运输状态 |
| 目标 | 实时更新每日发车动态 |
| 人工介入条件 | 95306 到站口径与专用线口径不一致、得胜台路线出现、车种与路线不匹配、放货批次缺失 |

### 7.4 发运动态更新

| 字段 | 内容 |
|---|---|
| 输入 | 已识别的九三大豆 95306 发车记录、人工设置的放货批次 |
| 触发条件 | 新发车数据到达或用户补充放货信息 |
| 处理动作 | 更新批次发运进度、累计车数、路线状态、异常说明 |
| 输出 | 九三大豆项目发运动态 |
| 当前说明 | 初始化阶段先建立项目和数据锚点，后续补充具体看板/报表/通知规则 |

## 8. 匹配规则

- 起运侧以锦州港仓库/高桥镇铁路发运为主要背景。
- 货物必须为大豆。
- 收货人或目的地应指向九三集团铁岭大豆科技有限公司。
- 常规目的体系为新台子站下的两条专用线：三三〇处专用线、九三集团铁岭大豆科技有限公司专用线。
- 集装箱路线应匹配三三〇处专用线；散粮车/K车路线应匹配九三厂内专用线。
- 得胜台出现时应默认标记为补充路线或异常路线，需要人工确认启用原因。
- 若 95306 只显示车站而不显示专用线，应结合车种、货物、收货人、用户放货单说明判断，不自动合并。
