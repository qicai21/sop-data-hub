## 问题 2:`bussiness-artifacts/` 下目录散落、同名多份、脚本路径不统一

**实证 —— 同名项目存在于两套并行根**:
```
./business/projects/jilin_jingang_jinzhou
./business/projects/zhongtang_special_steel
./wechat_images/business/projects/jilin_jingang_jinzhou      ← 与上重名
./wechat_images/business/projects/zhongtang_special_steel    ← 与上重名
```
即 `bussiness-artifacts/business/projects/` 和 `bussiness-artifacts/wechat_images/business/projects/` **两个 projects 根并存**,同名项目各一份,真身/副本不清。脚本引用也是混的(grep 显示 `bussiness-artifacts/wechat_images/business/projects/<canonical_id>/` 等多种写法)。

**期望**:
1. **审计所有脚本/项目**(`sop-data-hub/src`、`scripts`、`wx-ops-agent`)里对 `bussiness-artifacts` 归档路径的引用,确认**是否走同一个 canonical 根**;不是就收敛到一个。
2. 定一处**唯一项目归档根**(建议 `wechat_images/business/projects/<canonical_id>/`,因分类流水线已用此),把另一套 `business/projects/` 的内容合并/迁移后废弃。
3. 抽一个**路径常量/配置**(如 `BUSINESS_PROJECTS_ROOT`),所有脚本引用它,杜绝硬编码分叉。
4. `canonical_id` 与 `config/project_sops/*.yaml` 的 project id 一一对应(单一事实源)。

## 问题 3:`~/projects/repos` 顶层结构混乱,需整理

`~/projects/repos` 本身是个 git 仓(有 `.git`),却在顶层堆了大量松散文件/目录,且与子仓库(`sop-data-hub`、`wx-ops-agent`…)混在一起:
```

重叠目录:    doc / docs、prompts_and_reports / prompts_and_reports-main、
            business-system-docs、config、dashboard、data、migrations、orders、memory…
⚠ 残留旧名:  ops-data-hub  ← 已改名 sop-data-hub,这个旧目录还在(见 deprecated_concepts/项目重命名记忆)
其它:        empty_test_mcp、harness_tree_skill_lab 等疑似实验残留
```
另:`sop-data-hub` 内部也有轻度重复(`doc` 与 `docs`、`test-plan` 与 `test-plans`、`deprecated`/`notes`/`samples`)。

**期望**:
1. 厘清 `~/projects/repos` 到底该是"多仓父目录"还是"单仓",当前半仓半父目录的状态要收敛。
2. 清理 `ops-data-hub` 旧名残留(确认无引用后归并/删除)。
3. 合并重叠目录(`doc`/`docs`、`prompts_and_reports*`、`test-plan(s)`),删实验残留。
4. **先盘点出清单 + 影响面(谁还在引用)再动手**,别误删在用资产(参照 work-directly,但目录搬迁影响 import/路径,要先验证引用)。
