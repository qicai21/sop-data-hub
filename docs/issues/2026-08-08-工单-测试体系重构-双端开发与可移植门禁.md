## 0. 背景与目标工作流

### 0.1 新工作流（必须支持）

```
[MacBook 开发端]
  设计 / 写代码
  → make test          # 仅 unit + functional，可移植
  → git commit → push → GitHub

[本地运行端 / 原生产 Mac]
  git pull
  → 检查工作区 / 当前 commit
  → 安装或核对依赖（与 pyproject 一致）
  → make test          # 同一 portable 门禁
  → make smoke-runtime # 运行机必要条件（缺则 fail，不是 skip 充绿）
  → 按改动文件计算需重启的 daemon
  → launchctl kickstart …
  → health/log 最小验证
  → 失败时回退到前一已知良好 commit
```

约束：

1. **默认门禁（`make test`）不得依赖**：本机绝对路径、固定 `~/projects/repos/...` 布局、生产 `data/sop_agent.db`、真 95306 库、微信发送、鞍钢门户提交、本机 VLM `:8021`、launchd 是否已安装。
2. **同一 commit** 上，开发端与运行端执行 `make test` 应同绿/同红。
3. **pytest 永远不得写生产库**（无「允许写生产」开关）。live 只读真库时必须 SQLite `mode=ro`；任何写入只用 tmp 副本。
4. **unit/functional 无网络放行能力**；真网相关只存在于 live，且仍禁止微信发送与门户提交。
5. 业务铁律不变：生产链条可真发真传；**测试默认禁止外发**。

### 0.6 运行机发布门禁（契约；实现可分 PR/提交）

测试重构只保证「同一 commit 逻辑可验证」。运行与开发分离还需要发布步骤（本工单**定义契约**，完整脚本可 Phase 4 落地）：

```text
git pull
→ 检查工作区干净 / 记录 HEAD
→ 安装或核对依赖（uv sync / pip install -e ".[dev]" 与锁文件策略一致）
→ make test
→ make smoke-runtime
     - 配置 yaml 可加载
     - 生产 schema 版本/关键表只读检查（mode=ro）
     - runtime 目录可写性（runtime/ 本身，不是改业务库乱写）
     - 可选：关键 daemon plist 存在
     - 缺 95306 只读库 → **fail**（运行机发运必要条件）
     - 缺关键 launchd plist / 必需配置 → fail；可选观测能力缺失才允许显式 warn
→ 根据本次 diff 路径计算需 kickstart 的 KeepAlive daemon（对齐 START-HERE §4）
→ kickstart
→ 最小 health：进程在、log 无立即 traceback
→ 失败：checkout 上一已知良好 commit + 再 health（回滚步骤文档化）
```

- `make test-live-readonly`：可选深检，**不是**发布通过的充分条件。
- **禁止**用「live 全 skip」冒充发布通过。

## 2. 目标架构（三层）

```
  make test ──────────► tests/unit + tests/functional     可移植门禁
  make test-live-readonly ► tests/live（SOP_TEST_LIVE=1） 只读/本机布局，可选
  make smoke-runtime ─► 运行机发布必要条件（非 pytest 或极瘦脚本）缺则 fail
```

| 层 | 目录 | 允许 | 禁止 |
|---|---|---|---|
| **unit** | `tests/unit/` | 模块、`:memory:`/tmp sqlite、仓内 fixtures、生产 **schema 初始化 API** | 网络、生产库路径、home 业务目录必须存在 |
| **functional** | `tests/functional/` | 跨模块 + tmp 双库 + replay | 同 unit；**无**网络放行 fixture |
| **live** | `tests/live/` | 本机布局、真库 **mode=ro**、env 打开 | 写生产库；微信发送；门户提交；作为 `make test` 一部分 |

Marker：`unit` / `functional` / `live` / `replay`（replay ⊂ functional）。
**收集策略**：默认命令用**路径**限制，不用全局 `addopts = -m "not live"` 作为唯一手段（避免 live 模块 import 副作用与覆盖参数混乱）。live 目录内再要求 `SOP_TEST_LIVE=1`。

## 5. 安全轨、schema、回放

### 5.1 全局 `tests/conftest.py`（portable 强制）

| 项 | 行为 |
|---|---|
| `send_to_wechat` | 假 success（保留） |
| 鞍钢 upload / login 出站提交 | 调用即失败或假对象且**不发 HTTP** |
| 生产库路径写打开 | 检测到 repo 默认 `data/sop_agent.db`（及文档列出的生产路径）**写连接 → 测试 fail** |
| 读生产库 | portable 中 **禁止**；仅 live 且 `mode=ro` |
| **`allow_network`** | **不在此文件定义** |

### 5.2 仅 live：`tests/live/conftest.py`

- 无 `SOP_TEST_LIVE=1` → 整包 skip（或 collect 时 ignore，二选一写进 README，推荐 skip at import/fixture 层）。
- 只读 DB fixture：`sqlite3.connect(f"file:{path}?mode=ro", uri=True)`。
- **禁止**提供「解禁微信 / 解禁门户提交」的 fixture。
- 需要 HTTP 的连通性检查若存在：只允许对**显式配置的只读/健康 URL**，默认仍无；宁缺勿滥。

### 5.3 Schema

- **SOP 测试库**：优先 `data_agent.db` / 现有 `ensure_schema` / migration 入口在 tmp 文件上初始化，避免手写 DDL 与生产漂移。
- **Rail 最小库**：可自建列子集；另增 **字段契约测试**（生产查询 SQL 用到的列名 ⊆ 最小 schema 或文档列表）。
- 禁止复制一份长期不维护的全量 DDL 当唯一真相。

### 5.4 回放与匿名化（修订 F）

1. 优先 **一致性匿名映射**（同一真实车号 → 同一假车号，跨文件稳定），保留结构与数量关系。
2. ydid/箱号/车号仅当：私有仓、替换会破坏校验算法且 **人确认** 后可保留真实值。
3. 禁止入库：cookie、密码、手机号、本机绝对路径。
4. 体积：尽量小；**不以 500KB 为唯一标准**，以「最小可复现 + 脱敏」为准。
5. 升格目标：蓝鳍 50 车内嵌数据、至少一条 window_recover 案例 → `tests/fixtures/`。

```toml

  "unit: fast unit tests",
  "functional: cross-module temp DBs / fixtures",
```

### 7.2 Makefile

```makefile
PY=PYTHONPATH=src .venv/bin/python
PYTEST=$(PY) -m pytest

test:
	$(PYTEST) tests/unit tests/functional -q

test-unit:
	$(PYTEST) tests/unit -q

test-functional:
	$(PYTEST) tests/functional -q
```
