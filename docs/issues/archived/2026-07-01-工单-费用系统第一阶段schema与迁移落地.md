# 工单:费用系统第一阶段 schema 与迁移落地

- **类型**:架构实现 / 数据库迁移
- **发现日期**:2026-07-01
- **状态**:已处理
- **严重度**:高

## 背景

围绕 4 个 SOP 项目（中唐特钢、朝钢、吉林金钢、九三大豆）的费用系统方案已经完成文档论证，并已明确：

- `fee_*` 作为费用事实层
- `fee_allocation_override` 作为费用归属例外层
- `billing_reconciliation / billing_invoice / billing_settlement` 继续作为单据流转层
- `billing_cost_item` 不再作为未来通用事实主表，仅保留历史试运行样本意义

现阶段需要把方案从文档落到代码与数据库，先完成第一阶段最小可行 schema。

## 本工单范围

第一阶段仅处理数据库结构，不处理业务生成链与页面：

1. 新建费用事实层表：
   - `fee_item_catalog`
   - `fee_batch`
   - `fee_batch_member`
   - `fee_record`
2. 新建费用归属例外层表：
   - `fee_allocation_override`
3. 新建单证层表：
   - `doc_template`
   - `doc_instance`
   - `doc_instance_signoff`
4. 新建导入与审计层表：
   - `import_job`
   - `import_job_item`
   - `audit_log`
5. 对保留的 `billing_reconciliation / billing_invoice / billing_settlement` 补最小衔接字段
6. 提供可重复执行的 migration runner

## 明确不在本阶段处理

- 不生成任何费用记录
- 不把旧 `billing_cost_item` 数据迁入 `fee_record`
- 不生成 Word / PDF 单证
- 不接 UI
- 不跑历史补录

## 设计原则

- 迁移脚本必须幂等
- 不破坏现有 `billing_*` 历史数据
- 主库仍然是 `data/sop_agent.db`
- 先建“承载结构”，再接“业务逻辑”

## 验收标准

### 结构

- 主库新增目标表
- `billing_reconciliation / billing_invoice / billing_settlement` 获得最小衔接字段
- `rg -n "fee_|doc_|import_job|audit_log" scripts migrations` 可定位到正式 schema 与 runner

### 行为

- migration dry-run 可打印待执行 SQL
- `--apply` 可成功建表
- migration 可重复执行，不因已存在列/表报错

### 边界

- 旧 `billing_cost_item / billing_settle_override` 数据保持不变
- 主库中既有业务表无数据破坏

## 预期后续工单

第一阶段完成后，应继续拆至少 3 个后续实现工单：

1. `fee_item_catalog` 与项目合同/费目矩阵落地
2. 九三大豆散粮车线费用生成与现场确认单生成
3. `fee_record -> billing_reconciliation` 聚合链落地
