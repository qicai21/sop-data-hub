# 工单：Slack 货运看板结构化快照

- **日期**：2026-09-18
- **状态**：进行中
- **范围**：`scripts/cli_dashboard.py`、九三循环看板、结构化 `DashboardSnapshot v1` 输出；不改变发运事实与现有 Web 看板运行
- **关联计划**：`/Users/qicai21/macstudio-codex-slack/docs/issues/2026-09-18-slack-freight-dashboard-implementation-plan.md`

## 现象

当前局域网 Web 看板通过 `dashboard_web.py` 将 CLI 的 ANSI 文本转换为 HTML，`/api/dashboard` 仅返回 HTML 和页面生成时间。Slack App Home 需要结构化、可分页和可测试的数据，不能解析终端排版或 HTML。

## 边界

- 本工单只建立只读的看板快照数据契约与输出入口；不写 `sop_agent.db`、不写 95306 库，不触发微信/门户动作。
- 保留 CLI/Web 看板与 `dashboard-web` launchd 服务作为并行对照，未验收前不得停止。
- 现有 Web 渲染触发的已发重量派生投影刷新要单独审计；结构化快照调用本身必须无写入副作用。
- 九三循环的晨报池、95306 列位置与跟踪缓存来源/时间必须显式表达，不能从 ASCII 版面反推。

## 实施

- [ ] 冻结旧看板的字段、筛选、铁路计划日和样本对照。
- [ ] 提取版本化 `DashboardSnapshot v1`，与 ANSI/HTML/Slack Block Kit 解耦。
- [ ] 提供最小环境、只输出 JSON 的本机命令入口，并定义成功/失败退出码和输出限制。
- [ ] 为契约、空/坏库、时间边界、挂起刷新、九三来源与无写入副作用补回归测试。
- [ ] 与现有 CLI/Web 并行对账；差异必须记录或修复。

## 验收

- 结构化快照可在不运行 `dashboard-web` 的情况下生成。
- 固定测试样本与既有看板基础字段逐项一致，且不保留每项目 8 条的显示截断。
- 快照读取不导致业务库内容变化；95306 数据库始终只读。
- 未通过 Slack 并行验收前，局域网 Web 看板保持可用。
