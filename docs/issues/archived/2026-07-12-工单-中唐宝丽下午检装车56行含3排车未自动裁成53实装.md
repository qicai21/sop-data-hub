# 中唐宝丽下午检装车 56 行含 3 排车未自动裁成 53 实装

## 现象

2026-07-12 下午，中唐特钢 `宝丽` 在微信图片 `wx_2026-07_967` 中形成一张检装车通知单：

- VLM 抽取总行数：`56`
- footer 标注：`装车 53 节 / 排车 3 节`
- 当前候选：`inspection_ingestion_candidates.id=b485317e76463523caa58aaf77036ec776725743`
- 当前状态：`status=ambiguous`，`candidate_status=pending_review`
- 未进入 `wagon_shipments`

而 95306 已在 2026-07-12 14:53:30 - 15:02:07 形成对应 `53` 票，高桥镇 -> 汐子。

## 预期

系统应能：

1. 从通知单中识别 `56 行里有 3 条 defect/空排`；
2. 以 `53` 条非 defect 真车进入 95306 窗口恢复；
3. 自动匹配到 `宝丽 lot02`；
4. 完成 `wagon_shipments` 入库，并继续后续 Excel / 微信链路。

## 实际根因

### 1. 候选在进入执行器前就缺少 ship/destination/project

`workflow_task_db.id=640` 直接在 `candidate_field_check` 阶段退出：

- `reason=candidate_missing_ship_dest_project`
- `missing.ship=''`
- `missing.dest=''`
- `missing.project=''`

也就是说，这张图尚未进入“53 实装 + 3 排车”的业务裁剪阶段，先卡死在候选上下文缺失。

### 2. 当前上下文推断对该场景不稳

当前 `infer_candidate_context` 的两条主路都可能失效：

1. `text_fusion` 只看“同群 ±30 分钟”的 `departure_flow` 文本；
2. `evidence_scoring` 遇到“同船多 lot，且 ship/dest/cargo 相同”的情况容易打平。

本次宝丽下午图正好踩中：

- 图片在 `铁晟业务工作群`
- 同时段宝丽文本在 `中唐特钢发运群`
- `宝丽 lot01 / lot02` 同船同到站同货名

因此：

- 同群文本融合抓不到正确宝丽发车文本；
- 证据打分又无法在两个宝丽 lot 之间唯一决策；
- 候选最终未补全 `ship_name / destination / project_id`。

### 3. text_fusion 内部 release_batch 状态枚举也已过期

`infer_candidate_context.py` 中 text_fusion 命中船名后，查批次仍使用：

- `dispatch_status IN ('in_progress','suspended')`

而当前系统实际使用的是：

- `enriched / loading / all_loaded / tracking / delivered`

这意味着即便同群文本命中，当前实现也可能因为状态枚举不一致而拿不到宝丽的有效 batch。

## 影响

1. 下午这列 53 车不会自动入库；
2. `pending_review` 会残留；
3. 95306 已制票但业务链未闭环，容易造成“实际发车已完成、系统仍待人工”的错觉。

## 修复方向

1. 修正 `text_fusion` 的 release_batch 状态枚举，和当前 `release_batches.dispatch_status` 口径一致；
2. 扩展图片上下文推断，不仅限于“同群 ±30 分钟”，还应允许：
   - 同项目授权群之间的近时文本互证；
   - 同 ship/dest/count 的文本候选辅助；
3. 在“同船多 lot”场景下，若已有唯一 `loading` 批次且旧 lot 已 `all_loaded`，应优先把候选锚到仍在装运的 lot，而不是让字段留空；
4. 为“56 行含 3 条排车，footer=53，95306=53”的场景补功能测试，固定自动裁剪与自动入库行为。

## 验收

以 `wx_2026-07_967` 为回归样本：

1. 候选自动补全 `ship_name=宝丽 / destination=汐子 / project_id=zhongtang_special_steel`；
2. 自动排除 3 条 defect/空排行；
3. 自动以 53 实装车入 `wagon_shipments`；
4. 归属 `宝丽 lot02`；
5. 不再残留 `pending_review`。
