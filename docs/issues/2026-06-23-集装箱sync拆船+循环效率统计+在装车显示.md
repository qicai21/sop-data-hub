## ✅ 问题 1 已解决(2026-06-25)

**船归属事实源已确定**:港方逐船「货票」xlsx(新台子 sheet:车号+货票号+2箱号),个别"一车拉两船"靠箱级例外标注(如 货票GZDJW0496546 的箱1512630 归诚信、另一箱5804218 留和谐1)。货票号(GZD…)藏 95306 raw_core_json,经 ydid 桥接到系统 box。

**做法(仿散粮,box级)**:
1. 新表 `container_loading_notice`(box级:ydid+box_no→ship)。
2. 对账脚本 `scripts/reconcile_jiusan_containers.py`(可复用,每船发完/阶段性跑):读货票xlsx→建台账→重分船。用法见脚本头。
3. `sync_jiusan_harmony_wagons.py` 改多船版:窗口内按台账 box级拆船路由到各船 lot01;未命中台账→默认和谐1+WARN;挂错船自愈重路由。全九三集装箱船(和谐1/诚信/昆娜/玛格丽特)统一处理。

**验收(2026-06-25)**:和谐1 1780→1709箱(54250→48535t,回计划48090内);诚信 lot01 0→71箱;sync 重跑 0 重路由(台账一致)。**工作流**:港方给新货票清单 → 跑 reconcile → 自动重分船;daemon 平时按台账路由,新箱未对账前暂落和谐1+告警。

> 待补:混船守门单测(routing by 台账 + 自愈 + 默认兜底)。

## ✅ 问题 2 已解决(2026-06-25)

`jiusan_cycle_board._cycle_positions` 改用**节点时间戳推进**(港发车 departed→新台子到达 arrived→三三0交付 delivered),不再靠 95306 `status_name`(已制单)——制票滞后不再致在装列失显。逻辑:每列取最近一趟,已交付的列里**交付最早(返港最久)= 在装列(港重)**、其余=返空;到达未交付=新台子;发车未到达=途重。验收:在装=#1、新台子=#2、返空=#3,与节点时间戳/效率分析一致。在装列精确时刻仍可由晨报「港内配车 N道M节」进一步校准(留 §八)。

## ✅ 问题 3 已解决(2026-06-25)

`scripts/jiusan_cycle_efficiency.py`:按 home_cycle 分列、按 departed_at 分趟,从节点时间戳算各段时长(在途=到-发、卸货dwell=交-到、周转=下趟发-本趟交、整圈=下趟发-本趟发),给各列/整体均值 + 各列当前位置 + 下一节点 ETA(历史均值推),在途均值用于**到厂预测**(在途列:发车+在途均值=到厂)。实测和谐1:在途6.7h/卸货17.4h/周转36.4h/整圈58.9h。用法 `python scripts/jiusan_cycle_efficiency.py [--ship 和谐1]`。可后续并入看板。

## ~~问题 3(原始)~~:集装箱循环列各节点效率统计 + 到厂时间推算

**需求**:统计循环列每节点的循环效率,核心是**在途时间**及由此推算**到厂时间**。

**用户给的推算逻辑**:
> 若 #3 列已在三三0开始卸货交付,说明它前一列 #1 列应已卸完货、装好空箱、往锦州港发车了;**#1 到厂时间 ≈ #1 返港发车时刻 + 在途时间**。

**实现要点**:
1. **每列每趟打节点时间戳**(从 `wagon_container_shipments` 各状态 `ticketed_at`):港发车(已发车)→ 新台子到达(已到达)→ 三三0卸货交付(货物已交付)→ 返空发车 → 港到达。
2. **算各段时长**:在途(港→三三0)、卸装 dwell(三三0停留)、返程、整圈周期;按列/按趟均值 + 趋势。
3. **预测**:任一列在某节点 → 用历史均值推下一节点 ETA;尤其"在途时间"用于**到厂时间预测**(按用户逻辑:看 #3 卸货→推 #1 已返港发车→+在途=到厂)。
4. **载体**:新统计脚本或并入看板(可加"循环效率"小节:各段均值 + 各列当前位置 + ETA)。
5. **注意**:循环车号复用,按 `departed_at`/趟次(非 car_no)分趟;列号用 home_cycle + departed_at 指纹(见看板工单 §七车次语义)。
