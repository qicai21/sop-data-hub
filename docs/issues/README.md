# issues/ — 功能性问题工单

数据运维等会话发现的功能/缺陷问题写在本目录（`YYYY-MM-DD-简述.md`），
由「系统开发」会话处理（修改/开发/测试）。

## 费用工单不进本目录

费用结算、对账单、客户单价、开票、`fee_record` / `settlement_plan` 双轨等，一律写到 sibling 仓：

- 仓库：`/Users/qicai21/projects/repos/fee_manager`
- 排期：`fee_manager/docs/2026-07-19-排期-fee_manager与发运解耦专项.md`
- 工单：`fee_manager/docs/issues/`

本仓 `issues/` **只服务发运自动化**（检装、95306、lifecycle、Excel/上传等）。  
历史费用工单已在 `archived/` 的，保留作审计；**新建费用单禁止再开在 sop-data-hub。**

## 目录纪律

| 目录 | 含义 |
| --- | --- |
| `docs/issues/`（本目录根） | **未闭环**：待处理 / 进行中 / 部分完成 / 暂缓 / 待设计 |
| `docs/issues/archived/` | **已闭环**：已完成 / 已取消 |

**处理完即归档**：`git mv docs/issues/<工单>.md docs/issues/archived/`，
正文保留结案说明（改了什么 / 测试 / daemon 重启）。  
**禁止**把 `已完成` 工单长期堆在根目录——会制造「问题山」错觉。

## 状态枚举（唯一合法值）

写在工单标题下元数据行，格式：

```markdown
- **状态**：已完成
```

可选附注用破折号，不另造状态词：

```markdown
- **状态**：部分完成 — 主链已修；OCR 页脚金样例仍待补
```

| 状态 | 英文别名 | 目录 | 含义 |
| --- | --- | --- | --- |
| **待处理** | `open` | 根 | 已建单，未开工 |
| **进行中** | `in_progress` | 根 | 开发/联调中 |
| **部分完成** | `partial` | 根 | 主修复已落地，仍有明确尾巴 |
| **暂缓** | `deferred` | 根 | 明确不做/未部署/等用户拍板 |
| **待设计** | `design` | 根 | 方案未定，禁止当「已处理」 |
| **已完成** | `done` | **archived/** | 当次目标闭环（含「已处理」「已修复」历史同义词） |
| **已取消** | `cancelled` | **archived/** | 不做了，保留审计 |

### 废弃写法（归档时归一）

以下出现在历史工单中，**新工单不要再用**；归档时视为 `已完成`：

- `已处理` / `已修复` / `✅ 已完成(...)` / `claimed_done`
- 长句状态（「已处理;由 xxx 覆盖」）→ 状态行只写 `已完成`，细节放正文
