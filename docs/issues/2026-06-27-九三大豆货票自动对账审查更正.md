以用户提供的港方权威货票 xlsx(和谐1 / 诚信)逐货票比对当前 DB:
```
                  xlsx(权威)      DB           不符
和谐1 集装箱        855货票          855          ✓(含1张一车两船 GZDJW0496546 已正确拆:
                                                    TBJU1512630→诚信 / TBJU5804218→和谐1)
和谐1 散粮          320              320          ✓
诚信 散粮          425              ~426         ✓(差1为循环重票边界)
诚信 集装箱        125货票          35对+90错     ✗ 90张错挂和谐1
```
**错账=诚信 6/26(40张)+6/27(50张)集装箱货票全被挂到和谐1**(DB 和谐1 lot01 batch 实 945货票/1889箱 = 855真+90污染;存字段 855 还陈旧)。
**根因**:`sync_jiusan_harmony_wagons.py` 的 `DEFAULT_SHIP="和谐1"` 兜底——台账(`container_loading_notice`)只 reconcile 到 6/25,6/26/6/27 诚信新趟没入台账 → 未命中 → 默认堆和谐1。**与散粮回归(`2026-06-20` 工单)、集装箱拆船(`2026-06-23` 工单)同源**:台账不及时更新 + 默认落和谐1。

## 三、期望功能:自动对账(审查 → 更正),自愈

**目标**:把"港方给货票 → 手动 reconcile"变成**定时自动**:发现新货票 → 审查不符 → 更正台账 → 重同步 → 看板自愈。**数据不需人工补**。

1. **源采集**:监听 `九三大豆发运群` + `铁晟业务数据统计群`(确认群名);或直接扫 WeChat `msg/file/<YYYY-MM>/` 文件夹(按月滚动要跨月兜底)。识别大豆货票文件(和谐1/诚信、集装箱"新台子"sheet/散粮"散粮车"sheet),**多版本取最新**((5)>(4)>…/按 mtime)。
2. **审查(audit)**:对每船最新货票 xlsx,按 **hph(货票号)+ box_no** 逐箱比对 DB 现挂船;输出不符清单(应船 vs 实船、张数、日期)。**只读、可单独跑出报告**。
3. **更正(correct)**:把不符项写回台账(`container_loading_notice` / `bulk_loading_notice_wagon`)→ 触发 sync 重路由 → 各船 batch 重算聚合。**幂等、自愈**(再跑不符=0)。一车两船例外按 box 级保留(如 GZDJW0496546)。
4. **调度**:新增 launchd(或并入 jiusan-sync 链);每次 sync 前先跑对账更新台账,再路由。
5. **兜底口径修复(治本,呼应散粮/集装箱工单)**:`DEFAULT_SHIP` 不写死和谐1 —— 和谐1 集装箱/散粮发完后,未登记新箱**不再默认堆它**(加完成闸/默认落当前活跃船/挂 pending+告警)。否则每趟新船箱在对账跑到之前仍会瞬时漏挂(自愈前的窗口)。
6. **复用**:`reconcile_jiusan_containers.py`(集装箱)、`ingest_bulk_loading_notice.py`(散粮)做内核,套一层"扫文件夹→选最新→调用→重同步"的自动驱动。
