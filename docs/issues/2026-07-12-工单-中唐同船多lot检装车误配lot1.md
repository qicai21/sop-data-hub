# 工单: 中唐同船多 lot 检装车误配 lot1

## 现象

宝丽已有两个批次：lot1（2026-07-03，计划号 `90260700001`）与 lot2（2026-07-10，计划号 `90260700027`）。
2026-07-12 的 53 车应归 lot2，但检装车链按船名/到站/货类匹配到了仍为 `loading` 的 lot1。

## 根因

同船多 lot 并存时，`match_release_batch_by_ship_destination_cargo` 的候选排序没有把批次通知日期、当前 lot 及通知单事件时间组合为明确的优先级，导致较早 lot1 在 lot2 之前被选中。

## 数据更正

- 将本次通知单 `wx_2026-07_940` 的 53 个 `ydid` 从 lot1 精确迁移到 lot2。
- 同步迁移 `shipment_release_batch_matches`、候选 `release_batch_id`，重算两个批次的车辆数和已发重量。
- 旧 lot1 Excel/外发动作保留审计；重新生成并发送明确标注更正的 lot2 Excel。

## 修复目标

1. 多 lot 同船时按明确规则选择正确批次，不能仅因旧 lot 仍处于 `loading` 即优先命中。
2. 选择规则必须可测试，覆盖“同船、同到站、同货类、lot2 后建”的场景。
3. 不影响当前仍只有一个活跃批次的项目。
