# 工单: 九三和谐1散粮确认重量与船级对账清理

## 背景

在和谐1费用闭环验证中发现两个偏差:

1. `route_c_income` 已有确认重量落库, 但散粮费用生成时仍按批次标载重量计收入, 与业务确认口径不一致。
2. `billing_reconciliation` 按船重算时, 只按新分组 id 覆盖, 若结算方名称修正, 会残留旧记录。

## 目标

1. 散粮 route C 收入费目改为按 `shipment_weight_confirmation` 分摊后的确认重量生成。
2. 船级对账重算前, 清理同船旧 `billing_reconciliation` 汇总, 防止历史脏数据残留。

## 实施

1. 在 `jiusan_bulk.calc_fee_items()` 增加费目级重量覆盖能力。
2. 在 `fee_generate_jiusan_bulk.py` 中将 `route_c_income` 显式绑定到 `confirmed_batch_weight`。
3. 在 `fee_generate_jiusan_ship_reconciliation.py` 中, 按 `project + period + recognition_scope + recognition_key` 先删旧船级汇总, 再重新插入。
4. 补充针对收入确认重量覆盖的测试, 并重跑和谐1散粮费用与船级对账。

## 验证

1. `route_c_income` 的 `qty / pricing_basis_value` 应等于分摊后的确认重量。
2. `billing_reconciliation` 中同一 `ship:和谐1` 不再保留旧结算方名称记录。
