# 工单: 朝钢同批次更正通知单被已存在 batch_key 短路跳过
- **状态**：待处理 — 同 batch_key 更正通知单未 upsert 计划量

## 背景

2026-07-09 朝钢 `马兰幸福 lot02` 先收到一张 `10000吨` 出港计划通知单，后于当日 `15:24` 收到更正后的 `20000吨` 通知单。

业务上应以更正后的同批次通知单为准，更新 `release_batches` 中该 lot 的计划量。

## 现象

- 第二张 `20000吨` 通知单识别成功，也命中了同一个 `lot02`
- 但 `release_batches.batch_quantity` 仍停留在 `10000`
- 后续生命周期按 `shipped_weight >= planned` 判断完成，导致 `lot02` 被提前 `closed`

## 根因

`BusinessDataAgent.ingest_release_batch()` 在发现相同 `batch_key` 已存在时，提前 `skip`：

- 未继续执行后面的 `INSERT ... ON CONFLICT(batch_key) DO UPDATE`
- 导致同批次更正通知单只能“命中已有批次”，却不能真正更新计划量字段

## 预期修复

1. 同 `batch_key` 的重发/更正通知单，不应在 Python 层直接跳过
2. 应继续进入 SQL upsert，由 `ON CONFLICT(batch_key)` 完成字段更新
3. 已进入终态的批次仍由既有锁定逻辑保护，不被重发通知单改写

## 验收

- 针对进行中批次，重发同批次且数量变更的通知单后，`batch_quantity` 会被更新
- 不新增重复 release batch
- 已终态批次的“锁死不改写”测试继续通过
