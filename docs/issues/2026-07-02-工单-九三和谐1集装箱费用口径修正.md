# 工单:九三和谐1集装箱费用口径修正

## 背景

在核对 `和谐1费用汇总.xlsx` 时暴露出当前 `route_a_container` 费用生成口径有两类问题:

1. **箱类费用错误使用唯一箱号数**
   - 代码当前以 `COUNT(DISTINCT box_no)` 作为 `box_count`
   - 这会把同一箱体在项目内多次运输的事实压扁
   - 集装箱业务的有效计费事实不是“物理箱体唯一值”,而是**铁路运输事实/运单对应的箱次**

2. **一票两船的运费/标载未分摊**
   - 九三已知例外: `hph=GZDJW0496546`
   - 同一票下:
     - `TBJU5804218` 属于 `和谐1`
     - `TBJU1512630` 属于 `诚信`
   - 当前如果按整票汇总到单船,会把这类混票的铁路运费与标载全额吃进某一船

此外, `fee_generate_jiusan_route_a_container.py` 通过 `jiusan_container -> jiusan_bulk` 间接依赖 `python-docx`,导致在仅生成集装箱费用时也会因 `docx` 缺失而失败。

## 目标

1. `route_a_container` 的箱类费用基数改为 **`wagon_container_shipments` 行数(箱次)**,不再使用 `COUNT(DISTINCT box_no)`
2. 铁路票面类口径支持**按运单分摊**
   - 按 `ydid` 聚合票面 `marked_weight` / `freight_fee`
   - 再按该 `ydid` 在本船所占箱次数 / 全部箱次数进行分摊
   - 兼容一票两船场景
3. 去掉 `jiusan_container.py` 对 `jiusan_bulk.py` 的非必要导入耦合
4. 回归测试覆盖:
   - 箱次计费
   - 混票分摊
   - 集装箱费用脚本可在不装 `python-docx` 时导入

## 验收

- `和谐1 lot01` 生成费用时:
  - 箱类费用基数来自箱次/运输事实行
  - 国铁费按票面金额并支持混票分摊
- `GZDJW0496546` 不再被整票错误并入 `和谐1`
- 相关测试通过
