# 工单：货运看板隐藏检装车候选历史终态

- **日期**：2026-07-23
- **状态**：已完成
- **范围**：货运看板底部“检装车候选”状态统计

## 现象

系统状态面板长期展示：

```text
matched 58 · archived 32 · superseded 10 · matched_by_inference 5 ...
```

这些是候选处理历史的终态分布，不是当前故障，也不需要用户处理。长期展示造成信息噪声，用户无法据此判断系统是否有问题。

## 状态用途

- `matched*`：候选已匹配并进入后续流程；
- `archived`：历史候选已归档；
- `superseded`：重复或临时候选已被真实候选替代；
- `ignored_non_sop` / `cancelled_legacy`：非 SOP 或旧候选已终止。

这些状态仍用于幂等、去重和审计，不能删除数据或废除状态机，但无需进入日常货运看板。

## 改动

看板只查询并展示需要人工关注的开放状态：

- `candidate`
- `pending_match`
- `pending_review`
- `pending_95306_match`
- `pending_freight_info`
- `timeout_manual_review`

系统状态栏保留两个业务汇总：

- **挂起运单**：上述开放候选总数；
- **挂起出港计划通知单**：已识别建批但仍处于 `release_batches.pending_freight` 的数量。

两项始终显示数量，方便用户确认识别链正常；挂起运单大于零时再显示各状态明细。

## 验收

1. 历史终态仍保留在数据库中。
2. 看板不再显示 `matched / archived / superseded / matched_by_*` 等终态。
3. 始终显示“挂起运单 / 挂起出港计划通知单”汇总；有开放运单时显示状态明细。
4. 回归测试固定开放态过滤规则。
