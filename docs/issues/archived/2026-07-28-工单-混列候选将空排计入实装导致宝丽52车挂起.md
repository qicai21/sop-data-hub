# 工单：混列候选将空排计入实装导致宝丽52车挂起

## 状态

已完成

## 现象

2026-07-28 中唐特钢煤四检装车通知单识别结果为：

- 鞍子河 3 车；
- 宝丽 52 车；
- 空排 2 车。

95306 已在 16:12-16:13 制出鞍子河 3 票和宝丽 52 票。鞍子河已正常入库，
但宝丽候选被记录为 54 车并停在 `pending_review`，未生成发运 Excel。

## 根因

`BusinessDataAgent._ingest_single_inspection_payload()` 建候选时，
`car_numbers_json` 和 `wagon_count` 收集了所有有车号的行，没有排除
`defect=true` 的空排行。

后续执行器将候选车号视为人工/运维权威子集，形成：

- 候选车号 54：宝丽实装 52 + 空排 2；
- 95306 同窗 55：宝丽 52 + 鞍子河 3；
- 结果被误判为“通知单独有 2 + 窗口额外 3”，挂起人工复核。

## 修复

1. 候选 `car_numbers_json`、`wagon_count` 只记录非缺陷实装行；
2. `payload_json.rows` 继续保留空排行，确保原始识别结果可审计；
3. 增加回归测试，固定“实装 + 空排”候选只统计实装车；
4. 修正本次宝丽候选为 52 车并重跑标准链。

## 验收

- 宝丽候选车数为 52；
- 同窗鞍子河 3 车不再阻断宝丽精确子集；
- 宝丽 52 车写入 `wagon_shipments`；
- 发运 Excel 生成并发送至数据单发群；
- 外部动作日志完整记录生成、发送结果。
