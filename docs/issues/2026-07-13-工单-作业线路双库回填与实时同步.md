# 工单:作业线路双库回填与实时同步

- 日期: 2026-07-13
- 类型: 数据完整性修复 + 文本监听链路完善
- 状态: 已完成

## 问题

最近 20 天核查发现,`wagon_shipments` 与 `wagon_container_shipments` 的 `loading_line`
存在缺失。现有 `loading_line_backfill` 只查询和更新前者,导致吉林金钢、九三大豆的集装箱票
即使已有微信群作业线路文本,也无法回填。

## 目标

1. 线路回填同时覆盖两张运单表,按 `project + ship + 车数 + 制票时间窗` 守门;
2. 中唐/朝钢/吉林金钢只读 `铁晟业务工作群`,九三只读 `铁晟大豆业务内部沟通群`;
3. 新文本和后到 95306 票均能被常驻链路补齐,不依赖手工脚本;
4. 九三历史混发按已确认口径落七道或八道,不保留 pending;
5. 回填 2026-06-23 至今全部可确定缺失记录,复核缺失清单。

## 验收

- 两张表都能由同一线路回填模块更新;
- 新文本可立即更新已入库票,后到票由定期兜底扫描补齐;
- 最近 20 天缺失记录全部有作业线路或有明确的系统级待补告警;
- 覆盖双表、来源群隔离、九三兜底线路的回归测试。

## 实施结果

- `loading_line_backfill` 已同时支持 `wagon_shipments` 与
  `wagon_container_shipments`,按 `project + 日期 + 编组号 + 船名` 更新空线路字段。
- 授权群固定为:九三读取 `铁晟大豆业务内部沟通群`;吉林金钢、朝钢、中唐读取
  `铁晟业务工作群`。非授权群文本不参与线路回填。
- 九三无法精确匹配的历史组按确认口径兜底:散粮车七道、集装箱八道;不创建人工 pending。
- 已回填 2026-06-23 至今:吉林金钢集装箱 567 票、朝钢整车 225 票、中唐整车 106 票、
  九三散粮车 492 票、九三集装箱 777 票。复核两张运单表最近 20 天的空 `loading_line` 为 0。
- `text-watch` 每 5 分钟执行近 14 天的双表兜底扫描,仅更新空字段;新增复合索引
  `(group_name, msg_type, received_datetime)` 后,无缺失时扫描约 0.1 秒。
- 回归测试:22 passed。
