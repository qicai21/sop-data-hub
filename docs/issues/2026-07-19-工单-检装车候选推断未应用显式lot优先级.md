# 工单：检装车候选推断未应用显式 lot 优先级，宝丽 46 车卡住

- **提出日期**：2026-07-19
- **状态**：处理中
- **范围**：检装车通知单候选推断、宝丽 2026-07-19 46 车

## 现象

铁晟业务工作群 `wx_2026-07_1540`（07:15:51）为宝丽检装车通知单：页脚 `实装46节、排车2节`。46 个实装车已在 95306 制票，但系统未发送发运 Excel。

## 根因

图片识别已成功，通知单候选也已创建；但宝丽 `lot03`、`lot04` 都是 `enriched`，其船名、到站、品类证据同分。`infer_candidate_context` 将同分直接标为 `pending_review`，没有调用已存在的 `release_dispatch_match_rules.priority`。

用户此前已明确指定：宝丽后续发运优先填满 `lot03`，再填 `lot04`；对应优先级为 lot03=10、lot04=20。

## 修复

1. 候选证据同分时，如候选均为同一 project/ship/destination/cargo，调用通用 `match_release_batch_by_ship_destination_cargo`。
2. 若匹配器存在唯一最低 `priority`，则按该显式业务规则落库；不同业务实体同分仍保持 `pending_review`，不猜测。
3. 对本单将候选定向到宝丽 lot03，95306 权威 46 票入库后生成并发送一次 Excel。
