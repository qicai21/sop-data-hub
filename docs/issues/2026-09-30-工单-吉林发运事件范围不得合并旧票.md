# 工单：吉林发运事件范围不得合并旧票

- **日期**：2026-09-30
- **状态**：已完成
- **范围**：吉林金钢 `jljg_departure_text_chain`、分票计划、发运 Excel 与微信发送
- **theme**：T7_事件级外部动作幂等

## 现象

林加尼 `lot06` 的 `2026-09-29 20:52` 25车/50箱事件，95306 的 24 小时查询窗口
同时带回稍早的 38车。两批车均已正确入库，但执行器把 `skip_existing` 的 38车也纳入
本事件，生成了 63车 Excel；微信发送失败后，不能把这个累计文件作为 25车事件补发。

同时，已关闭的林加尼 `lot03` 仍留有状态为 `active` 的分票计划行。分配器只看计划行
状态，将其误认为可用计划，报出 `all active plans already full`，令任务误标失败。

## 修复

1. 容器项目的事件范围按当前 `source_message_id + batch_id + YDID` 收口；拒绝按整批兜底。
2. 分票计划必须同时满足计划行 `active` 且父 `release_batch` 为 `enriched/loading` 才参与分配。
3. 外部动作由失败恢复为执行成功时，清除遗留失败原因，避免审计面板显示假失败。
4. 为三个规则补功能回归测试。
