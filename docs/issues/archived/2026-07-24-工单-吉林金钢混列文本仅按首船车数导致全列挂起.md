## 根因

`jljg_departure_text_chain` 的输入模型仍是单一
`ship_name + car_count + release_batch`，没有保存和执行同一列中的多船顺序分段。
`parse_departure_text` 只取文本中的首个车数和首个船名。

## 修复要求

1. 吉林金钢发运文本支持提取同一列中的多个船名、车数和可选序号范围。
2. 分段总车数必须与 95306 本次事件的货票数一致；不一致时继续挂起，禁止强配。
3. 货票按稳定事件顺序分段，每个分段独立匹配开放 release batch。
4. 同一物理列可跨 batch 生成一张发运 Excel，并按各自订单信息上传收货人平台。
5. 添加稳定测试，至少覆盖本次 `马兰希望22 + 富翔7 23`、序号 39 作废后共 45 车。
6. 本次历史事件按人工确认清单补偿：马兰希望 lot6 22车44箱；富翔7 lot1
   23车46箱；作业线路煤三。
