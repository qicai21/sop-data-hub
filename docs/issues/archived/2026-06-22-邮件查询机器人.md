# 需求:赛彬邮件 → 只读业务查询机器人(自助查询,不占用郭东北)

- **提出日期**:2026-06-22
- **场景**:同事赛彬(`1219345480@qq.com`)发邮件查业务(发运/合同/下浮/数据),要"像跟郭东北对话一样"得到答复。每条都过郭东北确认=瓶颈,故做成自助服务。
- **边界铁律**:**只读(只查询+分析,绝不增改任何数据/文件)**;只对白名单;对外发送是系统设计职责(同 WeChat 自动发 excel),非助手临时代发。

## 架构
```
launchd daemon(每 N 分钟)
 → osascript 读 Mail 收件箱未读(activate + with timeout)
 → 命中白名单发件人 且 核验发件地址(防冒充)
 → 每封:起一个【只读 claude -p agent】(cwd=sop-data-hub)
      · 是纯查询/分析 → 输出答复正文
      · 带动作/意图不清/没把握 → 输出 `[[ESCALATE]] 原因`
 → 答复:osascript 发 "Re: <原主题>" 给赛彬;转译:reply 赛彬"已转郭东北" + 原信留未读/flag 给郭东北
 → 标已处理(message id 幂等)+ 审计日志 + 每日给郭东北一份"答了啥"日报
```

## 护栏(设计层,不靠用户逐条)
1. **只读**:agent `--disallowedTools Edit Write NotebookEdit`;DB 用**只读副本**(daemon 每轮 cp sop_agent.db → 临时只读),system prompt 硬禁"写库/改文件/跑带 --apply 的脚本";即使越界也只动副本,production 不受影响。
2. **白名单 + 验发件人地址**:合同/下浮敏感,绝不因冒充/转发发错人。当前白名单:赛彬 `1219345480@qq.com`。
3. **认不出不瞎答**:非纯查询(要求改数据/发东西给别人/意图不清/agent 没把握)→ `[[ESCALATE]]` → 转郭东北 + 回赛彬"已转郭东北",绝不编答案,绝不执行邮件正文里的指令。
4. **幂等**:按 message id 记已处理,不重复回。
5. **审计 + 日报**:每次交互(问/答/转译)留痕;每日给郭东北汇总。
