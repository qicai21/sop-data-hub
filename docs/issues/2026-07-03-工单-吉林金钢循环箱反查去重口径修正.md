# 工单：吉林金钢循环箱反查去重口径修正

- **日期**：2026-07-03
- **类型**：缺陷修复
- **项目**：吉林金钢

状态：已处理
## 背景

吉林金钢 `马兰希望 lot03` 在 `2026-07-02` 晚间 `23车 46箱` 补跑成功后，门户反查仍报：

- `verify(per-event): duplicate=7`

排查发现，这 7 个箱并非本次重复上传，而是**同一集装箱执行循环运输**：

- 锦州 -> 四平 -> 锦州 -> 四平
- 同一箱号在不同日期、不同车号下出现 2 次

旧口径把“吉林金钢集装箱项目”的唯一性键写成了 **箱号**，因此把合法的循环箱复用误判为重复。

## 根因

`factory_verify.py` 的 per-event 判定逻辑：

- present：按箱号是否出现
- unique：按箱号出现次数是否大于 1

这适用于“箱号不复用”的静态假设，但**不适用于循环箱业务**。

## 修正口径

对吉林金钢集装箱项目，门户反查的唯一性键改为：

- **`箱号 + 车号`**

判定规则调整为：

1. 本次上传的每个 `箱号+车号` 组合都必须出现在门户返回中
2. 每个 `箱号+车号` 组合在门户返回中必须唯一
3. 同箱号历史复用但车号不同，不再计入 duplicate

说明：

- `extra` / `total_match` 仍保留作观测字段
- `missing` / `duplicate` 的成败判定，以本次事件键集合为准

## 落地范围

- `src/sop_hub/sop/factory_verify.py`
  - 新增 `箱号+车号` 唯一键支持
  - 吉林金钢集装箱项目自动使用复合键
- `src/sop_hub/sop/executor_runner.py`
  - per-event verify 调用时传入事件级 `box_no|car_no` 键集合
- `tests/test_factory_verify_per_event.py`
  - 补充循环箱跨趟复用的测试样例

## 验收

- 同箱跨趟复用、但车号不同，不再报 duplicate
- 同箱同车真正重复时，仍能报 duplicate
- 不影响普通整车项目按既有口径反查
